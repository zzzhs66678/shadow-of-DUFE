# 小影：付费助理与校园连接方案

最后更新：2026-07-29

本文只记录“小影”、白果云同步和图书馆预约的当前有效方案。课程数据和主站事实仍以
`CURRENT_STATE.md` 为准，计划优先级以 `ROADMAP.md` 为准。

## 一、产品定位

- 小影是邀请码 VIP 功能，普通用户不显示入口。
- 核心不是通用聊天，而是“东财学生的学期托管助手”。
- 付费价值集中在自动同步遗漏信息、基于真实课程资料学习、动态调整学习计划和经确认执行校园任务。
- 普通课表、空教室、课程资料和今日学习台不得依赖 AI。

## 二、数据和算力放置

阿里云 ECS 继续负责：

- 网站和轻量 API。
- 用户账号、VIP 权限、课表、日程、作业和结构化同步记录。
- 已确认任务的短期队列、幂等键和审计记录。

ECS 不负责：

- 长期保存白果云或“我去图书馆”Cookie。
- 高频抢座、全域扫描、远程签到或占座。
- 大量课件原文件、视频、向量索引和模型推理。

大文件应逐步迁移到对象存储或外部网盘；ECS 只保存文件关系、权限、哈希和下载地址。
AI 推理由模型供应商完成，ECS 只做鉴权、工具编排、限额和流式转发。

## 三、小影本地执行器

推荐建立一个独立的“小影本地执行器”，首版可以复用
[EJianZQ/IGoLibrary](https://github.com/EJianZQ/IGoLibrary) 的领域模型和接口层。

执行器运行在用户自己的电脑：

1. 用户在本地完成微信或学校系统授权。
2. Cookie 进入 Windows Credential Manager、macOS Keychain 等系统凭据库。
3. 云端只保存设备公钥、能力范围和最后在线时间。
4. 执行器主动连接东财之影，领取属于该设备的短期签名任务。
5. 敏感操作先在手机显示预览，用户确认后才执行。
6. 执行结果只回传座位、时间、状态和错误码，不回传 Cookie。

不直接复用 IGoLibrary 当前带 `token` 的临时公网控制地址作为正式连接协议。正式配对应使用
一次性配对码、设备密钥、短期任务令牌、签名校验、幂等键和可撤销设备授权。

### 第一版允许的图书馆能力

- 查询当前预约。
- 读取用户收藏的常用座位。
- 查询指定座位是否可预约。
- 经用户确认后进行一次普通预约或明日预约。
- 经用户确认后取消预约。

### 第一版明确不做

- 高频抢座和全域捡漏。
- 反复取消后重新占座。
- 远程蓝牙签到或伪造位置。
- 未经用户确认的预约和取消。
- 把 Cookie、授权链接或控制令牌交给 AI 模型。

IGoLibrary 仓库声明使用 MIT License，但其许可证中的版权人和年份仍是占位文本。商业产品复用前应
保留仓库的许可证与来源说明，并主动联系作者确认商业集成边界；同时需要核对“我去图书馆”和学校的
最新使用规则。

## 四、白果云同步

目标是把用户自己的白果云课程信息同步为东财之影的结构化日程，而不是镜像白果云网页。

### 同步内容

- 课程及教学班标识。
- 课程通知。
- 作业标题、发布时间、截止日期和状态。
- 考试或课程活动时间。
- 用户主动选择同步的附件元数据。

### 推荐流程

1. 本地执行器打开或复用用户已登录的白果云会话。
2. 适配器读取用户明确授权的课程和作业数据。
3. 在本地转换成统一 `ExternalCourse`、`ExternalAssignment`、`ExternalEvent`。
4. 删除 Cookie、页面令牌和无关个人字段。
5. 使用稳定外部标识和内容哈希上传结构化记录。
6. 云端按 `source + externalId` 幂等更新，不重复创建日程。
7. 删除或改期在页面上提示用户确认后再影响个人日程。

在没有官方 API 或授权说明前，只做单用户、低频、可撤销的验证；不得把学校或第三方系统的
会话凭据集中保存到主站。

## 五、AI 工具边界

小影只看到工具返回的最小结构化数据。建议首批工具：

- `get_today_overview`
- `list_external_assignments`
- `find_free_study_blocks`
- `find_empty_rooms`
- `search_course_materials`
- `draft_week_plan`
- `create_calendar_items`
- `preview_library_reservation`
- `confirm_library_reservation`

读取类工具可直接运行；新增日程等本系统可撤销操作需要一次确认；图书馆预约等外部写操作必须使用
“预览—明确确认—执行—审计”四步流程。

## 六、实施顺序

### X0：单用户可行性验证

- 不接入主站真实 VIP。
- 给本地执行器增加只读状态、收藏座位和普通预约的窄接口。
- 验证电脑保持运行时，手机能发出一条已确认任务并收到结果。
- 验证白果云能稳定导出课程和作业的最小结构，不保存 Cookie。

### X1：安全配对

- 邀请码、账号权益和设备配对。
- 设备公钥、短期任务令牌、幂等与审计。
- 设备离线、Cookie 失效和任务超时提示。

### X2：课程同步

- 外部课程与本站课程的人工确认映射。
- 作业、通知和考试进入日程。
- 更新、删除、重复和时区回归测试。

### X3：小范围 VIP

- 先开放给少量邀请用户。
- 限制每日同步和预约次数。
- 记录成功率、失败原因、人工确认率和用户节省时间。
- 通过稳定性、规则与隐私审查后再收费扩大。

## 七、验收底线

- 云端数据库、日志和报错中都不能出现学校 Cookie、授权链接和第三方控制 token。
- AI 模型输入中不能出现上述敏感凭据。
- 用户能查看并撤销本地设备授权。
- 外部写操作都有明确确认、幂等键和审计记录。
- 设备离线时不得假装任务成功。
- 第三方接口变化时核心课表、空教室和资料功能仍可使用。
