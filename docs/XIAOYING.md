# 小影：VIP 校园助理

最后更新：2026-07-30

本文件只记录“小影”、白果云同步和图书馆预约的当前有效方案。主站事实以
`CURRENT_STATE.md` 为准，实施优先级以 `ROADMAP.md` 为准。

## 一、产品原则

- 小影是邀请码 VIP 功能，普通用户不显示入口。
- 默认邀请码在本地验证阶段为 `fjbadguy`，只能由服务端验证，数据库保存加盐哈希。正式环境还必须配置 1—500 次批次上限，事务内原子消费；轮换新码会废止旧码并重置新批次计数。
- AI 是可选入口。不开启 AI 的 VIP 仍能用完整的白果云同步和图书馆手动操作。
- 每位 VIP 自带模型 API 密钥；密钥只在专用服务端加密保存，不进入浏览器持久存储。
- 手动 UI 和 AI 共用同一校园动作服务，不维护两套业务规则。
- 用户只看到连接状态、同步结果、预约预览和错误提示，不需要理解 Cookie、令牌或接口实现。

## 二、当前架构

### 本地验证

`xiaoying-executor` 使用：

- Node.js 本地服务和移动端自适应验证台。
- SQLite 保存测试用户、VIP 权益、会话、连接状态、结构化同步记录和审计。
- AES-256-GCM 加密模型密钥和第三方授权包。
- 自动生成的本地主密钥与数据库分开保存在忽略提交的 `.local-data` 目录。
- HttpOnly、SameSite 会话 Cookie，不把测试会话令牌写入页面脚本。

### 正式邀请码内测

- 独立 `xiaoying` 容器只加入 Docker 私有网络，不映射 ECS 公网端口；Caddy 在
  `/campus-lab/` 去除路径前缀后转发。
- 独立 SQLite 持久卷只保存小影结构化数据；主密钥和邀请码由 600 权限服务器环境文件注入，
  不随镜像、Git 和数据库备份发布。
- 正式环境使用至少 12 位随机邀请码；路径限定的 `__Secure-` HttpOnly Cookie 只发送到
  `/campus-lab/`，站内普通账号 Cookie 与小影 Cookie 互不复用。
- 写请求要求 JSON 和主站同源 `Origin`；邀请码与公开配对接口按 IP 使用 SQLite 持久窗口限流，IP 只以主密钥 HMAC 摘要保存，重启不恢复配额。容器只读运行，
  使用非 root 用户，并限制 CPU、内存、进程数和日志体积。
- 用户可在“我的”页自行删除小影账号；删除会级联清理会话、连接密文、提醒、常用座位、
  同步结果和设置，并立即清除小影 Cookie。
- 小影页面设置 `noindex`、严格 CSP、禁止嵌入和禁止跨源资源读取；服务按完成子路径替换后的
  实际 HTML 为内联脚本、样式块与样式属性生成 SHA-256 白名单，不使用 `unsafe-inline`；主站
  `robots.txt` 同时禁止抓取该路径。

### 后续身份迁移

- 微信登录替换本地测试身份，匿名/本地数据合并到微信账号。
- SQLite 仓储接口迁移到 PostgreSQL，结构不依赖浏览器 `localStorage`。
- 正式主密钥由环境或密钥管理服务注入，不随镜像和数据库发布。
- 网站、同步计划和任务队列仍可运行在 ECS；大文件、向量索引和模型推理不放在系统盘。
- 第三方连接服务单独限流、审计和熔断，接口变化不得影响课表、空教室和资料。

## 三、白果云同步

### 已确认的数据路径

白果云当前网页通过请求头中的 `token`、`batchNo` 和 `fingerprint` 访问
`https://ginkgostu.dufe.edu.cn/student/...`；SSO 回调还提供用于换取新令牌的
`refreshToken`。因此同步不以长期 Cookie 为前提。

首批只读接口：

- 当前日期和教学周。
- 当前周课程、网络课程和无固定周次课程。
- 作业列表。
- 课程通知列表。

### 同步流程

1. 用户在受控的白果云页面完成一次学校/微信授权。
2. 连接层只提取同步所需的授权包并立即加密，不要求用户填写学校密码。
3. 定时或手动同步先调用只读接口；遇到过期先尝试刷新令牌。
4. 刷新失败时连接状态改为“需要重新授权”，旧的结构化课表和作业仍可查看。
5. 返回数据转换为 `ExternalCourse`、`ExternalAssignment`、`ExternalEvent` 和
   `ExternalNotification`。
6. 云端按 `user + source + externalId` 幂等更新；同一作业不会重复创建。
7. 新增、改期和删除先更新外部记录，再由日程投影层统一合并到今日学习台。

页面、日志、任务和 AI 输入中都不得出现白果云令牌、刷新令牌或指纹。

## 四、图书馆预约

正常预约能力参考并适配
[EJianZQ/IGoLibrary](https://github.com/EJianZQ/IGoLibrary)：

- 一次性微信授权换取会话。
- 验证会话和识别过期。
- 加载场馆列表和座位布局。
- 查询当前预约。
- 查询指定座位。
- 普通预约和明日预约。
- 取消预约。

东财之影使用自己的 JavaScript 数据契约、加密仓储、安全确认流和 UI，不直接嵌入原 Avalonia
界面。来源与许可说明见 `xiaoying-executor/THIRD_PARTY_NOTICES.md`。

### 外部写操作

所有真实预约和取消都必须经过：

1. 读取最新座位/预约状态。
2. 生成短期有效预览。
3. 用户明确确认。
4. 使用幂等键执行一次。
5. 保存不含凭据的审计结果。

### 明确不做

- 无上限高频抢座和无范围限制的连续扫描；对应的定时预约与低频空位发现仍保留。
- 伪造 GPS、蓝牙或到馆状态。
- iBeacon 到馆检测、远程签到和一键签到；用户已明确取消整项签到功能。
- 没有明确周期上限的反复取消或重约；预约守护只按用户设置的真实过期时间执行，最多三个周期，失败即暂停。
- 未经确认的自动预约和取消。
- 把授权包或第三方控制令牌交给模型。

## 五、AI 工具层

AI 只调用与手动 UI 相同的结构化工具：

- `get_today_overview`
- `list_external_assignments`
- `find_free_study_blocks`
- `find_empty_rooms`
- `search_course_materials`
- `draft_week_plan`
- `create_calendar_items`
- `list_library_venues`
- `check_library_seat`
- `preview_library_reservation`
- `confirm_library_reservation`
- `preview_library_cancellation`
- `confirm_library_cancellation`

读取类工具可直接运行；本系统内可撤销写操作需要一次确认；第三方写操作必须完整走
“预览—确认—执行—审计”。模型看不到密钥和第三方授权包。

## 七、验收底线

- 数据库导出、日志、报错、审计和模型输入中都没有明文凭据。
- 对外报错只使用审核过的稳定错误码与固定文案；未知异常不得直接返回 `error.message`。
- 用户能查看连接状态并随时断开第三方连接或删除模型密钥。
- 授权过期不会删除已经同步的个人日程，也不会假装同步成功。
- 外部写操作都有明确确认、幂等键和审计记录。
- 第三方接口变化时，主站核心课表、空教室和资料仍可使用。
- 普通用户不承担 VIP 同步和 AI 带来的资源成本。
