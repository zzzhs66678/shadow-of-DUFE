# 东财之影正式发布实施计划

最后更新：2026-08-03

## 1. 需求与事实来源

- 本轮唯一产品需求与最终验收标准：仓库根目录 `MASTER_RELEASE_BRIEF.md`。
- 当前已生效事实：`docs/CURRENT_STATE.md`。
- 本文件只记录实施顺序、验收证据和提交边界，不扩展总任务书的产品范围。
- `docs/PROGRESS.md` 是执行状态与下一步的唯一入口；任何“完成”都必须有测试或人工验收证据。

当前开发分支：`codex/release-upgrade`。禁止直接在生产环境执行不可逆操作；所有变更先经独立提交、Pull Request 和 staging 验证。

## 2. 技术基线

| 领域 | 当前方案 | 本轮方向 |
|---|---|---|
| Web | React 19、TypeScript、vinext；主界面集中于 `DufeHubV2.tsx` | 保留 SSR 外壳，按领域拆分页面、数据与交互原语 |
| 账号 API | Node.js HTTP 服务，单独容器 | 扩展真实认证、资料、社区、通知、管理 API |
| 主数据库 | PostgreSQL 17，校验摘要的顺序 SQL 迁移 | 继续作为账号和社区的唯一权威数据源 |
| 匿名数据 | 浏览器 `localStorage` | 先做匿名/账号作用域隔离，再逐步迁移到 IndexedDB 适配层 |
| 课程数据 | Excel 离线生成 JSON | 保留 Course—Section—Meeting 三层事实；为检索生成轻量索引 |
| 学习资料 | 只读文件目录与静态清单 | PostgreSQL 保存可检索元数据，文件仍独立存储，兼容旧链接 |
| 小影 | 独立 Node + SQLite 容器 | 本轮先加固并保持故障隔离；不冒险直接迁移生产数据 |
| 边缘与发布 | Caddy、Docker、不可变 release、原子切换 | 先 staging，验证后才进入生产审批 |

## 3. 里程碑

每个里程碑必须依次完成：实现 → 对应测试 → 修复失败 → 更新 `PROGRESS.md` → 创建语义清晰的提交。

### M0：仓库审计、运行基线与技术计划

范围：

- 完整核对仓库、现有页面、技术栈、数据库、部署、未提交改动和素材来源。
- 独立完成产品/UX、前端/视觉/QA、后端/安全评审。
- 审计用户提供的教师评价工作簿，只输出结构与风险，不直接导入原始内容。
- 建立本计划、进度、安全审计、架构决定和部署检查表。

验收证据：现有回归、认证 API、小影、构建、SSR、依赖审计和多宽度页面基线；文件与 Git 状态可追溯。

提交边界：`docs: establish release upgrade baseline`。

### M1：用户注册、登录、资料保存、云同步与管理员底座

范围：

1. 修复同浏览器 A 账号退出后本地数据可能合并进 B 账号的 P0 问题；匿名数据与每个账号严格分区，合并需显式选择。
2. 实现用户名、邮箱、密码注册与登录；密码使用 Argon2id；补齐退出、会话轮换、密码重置令牌、反枚举和 IP+账号限流。
3. 扩展公开资料：唯一用户名、头像、可选学校账号、验证状态、注册与最后登录时间、账号状态和角色。
4. 实现安全头像上传或可替代的默认头像路径；验证内容、魔数、尺寸、体积并移除 EXIF。
5. 实现服务端 RBAC、管理员 TOTP、用户管理、账号禁用/恢复、统计与 append-only 审计日志。
6. 保留微信 OAuth 适配边界；没有正式 AppID/AppSecret 时不显示伪入口。

验收：真实注册/登录；A→退出→B 无数据串号；两设备同步一致；普通用户所有管理接口均 403；管理员关键操作有审计；迁移重复执行安全。

提交建议：账号隔离、凭据认证、资料/头像、RBAC/TOTP/后台分别提交。

### M2：课程资料检索重构

范围：

- 建立独立 `/materials` 与 `/materials/:material_id` 路由和真实资料 API。
- 索引标题、课程、教师、标签、类型、学期/年份；列表直接给出预览/下载，不进入教学班选择。
- 兼容现有有效文件 URL；补齐首次、加载、无结果、网络失败、失效、无权和同名实体状态。
- 搜索状态进入 URL；键盘方向键、Enter、Escape 与移动触控真实可用。

验收：目标资料最多两次主要操作打开；课程、教师、资料查询只返回资料；手机与键盘路径通过 E2E。

### M3：`teacher_id`、教师评价与可审计数据导入

范围：

- 新增稳定 UUID `teacher_id`、别名、学院、历史课程、来源、更新时间和同名区分。
- 建立来源教师键映射、导入批次、字段映射、内容摘要、不可变逐行错误、append-only mutation、预检、幂等更新与批次回滚。
- 将用户提供工作簿视为“历史整理内容”：先脱敏、过滤人身攻击和私人信息，绝不冒充当前注册用户。
- 教材按学期和教学班保存多个教材项；占位 ISBN、异常日期和“不指定教材”保留原始状态，不覆盖目录课程上的单一教材字段。
- 教师详情和五个教学相关评价维度统一供课表、课程、教师索引和社区使用。

验收：同名教师不误合并；重复导入不重复插入；失败报告可下载；原始高风险评论未经审核不可公开。

### M4：社区、回复、通知、举报与审核

范围：

- 主题、教师评价、两级回复、点赞、收藏、屏蔽、折叠、编辑窗口、软删除、分享与游标分页。
- 回复、提及、内容处理和公告通知；未读计数、单条/全部已读和删除目标降级页。
- 举报队列、审核案件、隐藏/恢复/删除、封禁与申诉所需审计信息。
- 服务端校验、纯文本/白名单富文本、参数化 SQL、CSRF、账号+IP 限流、反刷唯一约束。

验收：两用户互动和通知闭环；删除引用不崩溃；普通用户不能越权；管理员处理举报全程留痕。

### M5：全站设计系统、游戏化交互与文案审计

范围：

- 保留 V18“纸、墨、朱印、校园时间轨”原创方向；今日学习台继续功能优先，校园照片只在“我的”。
- 合并多代 CSS 覆盖，建立唯一 Token、交互原语和字体回退；消除随机圆角、阴影和绿色残留。
- 每页最多一个标志性动态表达，所有动画可中断并遵循 `prefers-reduced-motion`。
- 用具体校园语言重写标题、按钮、字段说明、错误、空状态、隐私、社区规范和管理员提示。

验收：核心任务不比基线多步骤；无侵权素材；主要页面统一；文案不暴露开发提示词或未实现承诺。

### M6：移动端、无障碍与性能

范围：

- 覆盖 320、360、375、390、414、768px 与横屏；关键触控目标至少 44px。
- Link、Dialog、Combobox、Toast/live region、Field/Error、Confirm/Undo 统一可访问行为。
- 拆分主客户端单体；首页不再阻塞加载全量 3MB 课程数据；生成轻量今日数据和搜索索引。
- 长列表分页/虚拟化，图片与字体优化，去除整页 520ms 空白转场。

验收：键盘关键路径可完成；axe 无 critical/serious；无横向溢出；staging 目标 LCP≤2.5s、INP≤200ms、CLS≤0.1。

### M7：身份、权限、输入、上传、限流与后台安全审计

范围：修复 `SECURITY_REVIEW.md` 中全部高危项；核对 XSS、CSRF、SQLi、IDOR、SSRF、开放重定向、路径遍历、文件伪造、暴力破解、用户枚举、Mass Assignment、敏感信息和管理员暴露。

验收：高危项状态全部为“已修复并验证”；安全头、错误脱敏、依赖、密钥、数据库最小权限、限流和备份恢复门禁通过。

### M8：单元、集成与关键路径 E2E

范围：建立真实行为测试，不以源码正则代替用户路径。覆盖注册、资料编辑、跨设备同步、资料搜索、教师评价、两用户回复与通知、管理员举报处理、普通用户后台拒绝和移动端。

验收：主站、auth-api、小影、迁移、API、权限、E2E、axe、构建全部进入 CI；失败不能被忽略。

### M9：构建、迁移验证与部署准备

范围：临时 PostgreSQL 从零迁移与重复迁移、备份恢复演练、Docker 构建、健康检查、staging 部署（仅在已有安全环境时）、监控与回滚演练。

验收：`DEPLOYMENT_CHECKLIST.md` 的生产前项目全部通过；生产凭据缺失必须明确列出，不伪造上线。

### M10：Pull Request 与最终交付

范围：更新 README、环境变量、管理初始化、素材许可、部署/回滚说明；推送功能分支并创建可审查 PR；按总任务书十四项结构交付。

验收：提交边界清晰、CI 通过、PR 可复核，所有状态区分“已验证 / 缺生产凭据 / 测试失败 / 未实现 / 外部阻塞”。

## 4. 测试门禁

- 快速回归：领域单元测试 + 相关 API 集成测试。
- 每个服务：独立安装、生产依赖审计和测试。
- 数据库：空库迁移、重复迁移、约束、幂等导入、回滚或前滚演练。
- 浏览器：Chromium 关键路径、7 个宽度、横屏、键盘、reduced motion、网络失败和长文本。
- 发布：全量 lint、构建、SSR、API、E2E、axe、Docker health、备份恢复与安全检查。

## 5. 明确不做的捷径

- 不以静态假数据、假二维码、前端隐藏按钮或内存 Map 冒充生产能力。
- 不把真实密钥、令牌、Cookie、管理员凭据或原始第三方授权包写入仓库和日志。
- 不按课程名或教师名做唯一标识；不破坏 Course—Section—Meeting 关系。
- 不直接把未审核的历史评价作为当前用户内容公开。
- 不复制第三方游戏、社区或 Sci-Hub 的受版权保护素材与具体 UI。
- 不在未完成迁移、回滚和 staging 验证前直接变更生产数据。
