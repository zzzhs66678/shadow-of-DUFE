# 东财之影正式发布架构决定

最后更新：2026-08-09

本文件记录本次正式发布中会持续影响实现的技术决定。产品范围仍以 `MASTER_RELEASE_BRIEF.md` 为准。

## ADR-001：PostgreSQL 是账号与社区的唯一权威数据库

**状态：接受。**

- 继续使用现有 PostgreSQL 17 和顺序 SQL 迁移。
- 根目录 D1/Drizzle 模板不承载本轮生产数据；在确认无调用后移除或明确标记为非生产模板，避免第二套 schema 来源。
- 浏览器数据只作为匿名模式与离线缓存；登录后的权威状态在云端。

## ADR-002：保留 Course—Section—Meeting 三层课程模型

**状态：接受。**

- `teacher_id`、资料与评价关联不能破坏课程号、教学班和多个上课时段的关系。
- 同名课程、同名教师都不是唯一标识；未选具体班级时不得猜教师或教学班。

## ADR-003：本地数据按匿名设备和账号分区

**状态：接受。**

- 匿名命名空间与每个 `user_id` 的账号命名空间互不读取。
- 退出登录只保留匿名可用状态，不把前一个账号的数据变成下一账号的“本地数据”。
- 匿名数据首次并入账号必须显式选择；默认以云端为权威，保留可审计的冲突处理。

## ADR-004：降级认证使用用户名、邮箱与密码，密码使用 Argon2id

**状态：接受。**

- 微信 OAuth 保留为可替换提供方；没有正式资质时不伪造可用状态。
- 密码、重置码和验证令牌绝不明文存储；一次性令牌只保存带服务器 pepper 的摘要、过期时间和消费时间。
- 登录响应统一，避免邮箱/用户名枚举；按 IP、规范化账号和设备组合限流。

## ADR-005：同源 API 与 HttpOnly 会话保持现有边界

**状态：接受。**

- 浏览器通过同域 `/api/auth/*`、`/api/materials/*`、`/api/community/*` 与 `/api/admin/*` 访问服务。
- 继续使用 Secure、HttpOnly、SameSite Cookie；敏感认证信息不进入 `localStorage`。
- 写请求服务端校验 Origin、内容类型、大小与业务字段；所有授权在服务端执行。

## ADR-006：管理员采用 RBAC、TOTP 和 append-only 审计

**状态：接受。**

- 普通账号、内容管理员与站长角色明确区分；入口隐藏不是权限措施。
- 高风险管理操作要求已验证 TOTP 的独立短时提升会话；提升令牌使用单独的 `__Host-`、HttpOnly、Secure、SameSite=Strict Cookie，并绑定原始基础会话，不能跨设备或跨会话继承。
- TOTP 密钥使用 AES-256-GCM keyring 加密，AAD 绑定因子与用户；恢复码使用独立 pepper 的摘要。匹配时间步与恢复码均由数据库原子消费，防止并发重放。
- 管理员只通过显式运维命令按已有账号初始化；不设公开 bootstrap token，也不自动提升首位注册用户。
- 审计记录保存操作者、动作、对象、请求 ID、脱敏前后状态和时间，普通用户无修改权限。
- 用户禁用、角色变更、基础/提升会话撤销和审计写入必须处于同一事务；恢复用户永远不会恢复旧会话。

## ADR-007：资料元数据进 PostgreSQL，文件继续独立存储

**状态：接受。**

- PostgreSQL 保存稳定 `material_id`、标题、类型、课程/教师/标签关系、hash、MIME、大小、可见状态和旧链接映射。
- 大文件不进入系统盘数据库；现有只读发布目录与未来对象存储通过存储适配器统一。
- 资料检索是独立路由，不依赖选择教学班。

## ADR-008：教师使用稳定 UUID，导入是可预检、幂等、可回滚批次

**状态：接受。**

- `teacher_id` 不由姓名直接生成；别名、学院和历史课程辅助人工消歧。
- 每次导入保存文件摘要、映射版本、创建/更新/跳过/错误计数与逐行错误。
- 历史评论必须经过敏感信息扫描和人工审核，发布时标明“历史整理内容”，不挂靠真实学生账号。

## ADR-009：社区使用两级回复与统一内容治理

**状态：接受。**

- 主题、教师评价和评论共享可治理的内容状态、举报、软删除、通知和审计语义。
- 回复只允许根评论与一层回复，避免移动端无限缩进。
- 点赞、收藏、屏蔽和举报使用数据库唯一约束和事务，不能只靠前端去重。

## ADR-010：公开路由可深链，保留旧 `?view=` 兼容

**状态：接受。**

- 新增 `/materials/:id`、`/teachers/:teacher_id`、`/community/topics/:id`、`/notifications` 和受保护的 `/admin`。
- 筛选、排序、分页和选中项进入 URL；导航使用真实 Link。
- 旧的 `?view=` 链接在迁移期重定向或兼容解析。

## ADR-011：视觉语言是“校园导视 × 学术档案 × 日月时间轨”

**状态：接受。**

- 保留纸白、炭墨、朱红和仅用于状态的松针绿；不恢复蓝色主视觉。
- 今日学习台只表达当前行动，校园摄影放在“我的”；每个一级页面最多一个标志性动态元素。
- 游戏感来自时间轨、任务状态、完成/撤销反馈，而非复制角色、Logo、音乐或具体游戏 UI。

## ADR-012：小影在安全迁移前保持独立故障域

**状态：接受。**

- 主站本轮认证与社区不能依赖小影可用性。
- 在完成加密数据迁移、双读核对、任务租约和第三方协议风险处理前，不对生产 SQLite 做不可逆合并。
- 未来合并身份时继续遵循外部写操作“预览—确认—幂等执行—审计”。

## ADR-013：迁移采用 expand—backfill—validate—cutover—contract

**状态：接受。**

- 所有生产表只做向前兼容的增量迁移；大表索引和回填与事务迁移器的限制分开处理。
- 破坏性 contract 阶段只能在兼容版本运行、备份验证和回滚窗口之后执行。

## ADR-014：真实行为测试是发布证据

**状态：接受。**

- 源码正则只作为静态契约，不替代 API、迁移、浏览器 E2E、axe 与权限测试。
- CI 必须独立安装、审计并测试主站、auth-api 与小影。
- 发布必须覆盖普通用户访问管理接口被拒绝、跨账号不串号和社区两用户通知闭环。

## ADR-015：社区保持独立信息空间，不挤占今日学习台

**状态：接受。**

- 社区使用独立 `/community` 与主题深链；今日学习台继续只承担当天课表、任务与空教室等高频效率功能。
- 五项主导航不增加第六项；社区入口放在“我的”和社区自身导航，通知入口只在已登录社区上下文出现。
- 社区视觉沿用纸、墨、朱线、金与松针绿，并以一条讨论时间线作为唯一标志性动态；不使用蓝色主视觉、照片背景或仿制第三方具体 UI。

## ADR-016：举报证据不可变，治理案件允许可逆中间态

**状态：接受。**

- 举报创建事务保存目标标题、正文、作者标签和取证时间；审核只读该快照，作者后续编辑或软删除不改写原证据。
- 隐藏、暂停和封禁属于可逆中间动作，案件保持 `reviewing`；隐藏内容只允许恢复或删除，生效制裁中的账号只允许解封，防止警告或驳回把仍有干预效果的案件提前关闭。恢复、删除、解封、警告或驳回只在对应状态允许时结束案件。
- 服务端按目标当前状态计算 `allowedActions`，界面只呈现该集合，数据库事务仍负责最终授权与状态冲突校验。

## ADR-017：全站颜色只从一组语义 Token 派生

**状态：接受。**

- `--dufe-paper/ink/red/pine/gold` 是全站色彩唯一事实；`--journal-*`、`--ds-*` 和页面局部变量只能作为兼容别名，不再自行定义近似色。
- 蓝色不再作为日程或状态视觉。为兼容浏览器中已有个人日程，数据枚举 `blue` 暂不破坏性迁移，但其用户名称和渲染都映射为炭墨；新建日程默认朱红。
- 今日学习台只承载当天任务和校园直达。校园影集、创作者幕后与知识开放致敬都归入“我的”，不能回流首页争夺主任务。

## ADR-018：教师来源身份、历史评价候选与教学班教材分层保存

**状态：接受。**

- `teacher_id` 是独立 UUID；工作簿来源使用 `(source_system, external_teacher_key)` 映射。姓名和学院不设唯一约束，只用于检索、快照和人工消歧，同学院同名也不得自动合并。
- 历史评价先进入私有 `teacher_review_candidates`，只保存脱敏候选和原文摘要；全部从 `pending` 开始，管理员批准后才事务性生成标注“历史整理内容”的公开评价，且不从历史文本推导五维评分。
- 教材按“学期 × 课程号 × 课序号 × 教师 × 教材项”保存并允许多项；目录课程上的旧单一教材字段不再作为新版事实来源。替换与回滚采用 `superseded/withdrawn` 版本状态，不硬删除。
- 预检行证据和实际 mutation 分表 append-only；auth runtime 对导入批次、行证据、mutation 和历史候选完全撤权，正式 apply 只能在独立受控数据库角色和真实 PostgreSQL 验证后开放。

## ADR-019：历史教师评价审核是一次性、事务化的提升权限动作

**状态：接受。**

- 候选脱敏正文和原文摘要是不可变证据；管理员决定另存于 append-only `teacher_review_candidate_decisions`，保留操作者显示快照、理由、批准正文和公开评价引用。
- 候选列表和 approve/reject 都必须绑定活动管理员、活动基础会话和同一会话的短期 MFA elevation；数据库函数在读写时再次验证，不能只相信路由层检查。
- 决策事务先按批次、候选固定顺序加锁。批准同时更新候选、创建标注“历史整理内容”的公开评价、写一次性决定和全局管理员审计；拒绝不创建公开评价。任一步失败全部回滚，并发后到请求返回状态冲突。
- importer 没有候选 UPDATE、决定表或公开评价写权限，只能执行固定 `search_path` 的专用回滚函数；已批准或已公开候选拒绝导入回滚。

## ADR-020：教师公开读取按稳定身份分层，姓名入口只做消歧

**状态：接受。**

- 教师列表与详情以 `teacher_id` 为资源标识；列表按规范化姓名、学院和 UUID 做 keyset 分页，同名记录不合并。
- 公开接口只返回可见身份、当前或待核对教学班与教材、已发布评价；私有候选、原文摘要、导入证据和内部身份状态不进入响应。
- 历史整理评价固定保留来源标签且不参与五维评分；五维均值只来自注册用户的结构化评分。
- 现有课表数据只有教师姓名，因此进入预填姓名的教师索引，由用户依据学院和教学班确认；只有未来数据带稳定 `teacher_id` 后才允许直达详情。

## ADR-021：用户教师评价是“当前用户 × 教师”的带版本私有资源

**状态：接受。**

- 客户端以 `/api/teachers/:teacher_id/my-review` 读取、创建、编辑或删除本人评价，不提交评价 ID、作者 ID、发布状态或来源字段；作者身份只来自活动站内会话。
- 每个用户与教师组合最多一条未删除评价。编辑和删除必须携带当前版本，数据库事务加锁后再次比较；并发旧写入返回冲突，不覆盖较新的正文或评分。
- 注册用户评价必须包含 NFKC 后 20—3000 字正文和五个 1—5 整数评分；历史整理评价继续使用空评分，不能经用户接口修改或转换。
- 用户删除评价采用软删除；账号注销时同一触发器允许仅执行作者去标识化与撤下，保留必要版本事实但从公开读取中移除正文，并且不得阻断账号删除。

## ADR-022：共享编辑型字段只统一交互语义，不抹平页面构图

**状态：接受。**

- `FormField` 统一标签、计数/提示、44px 最小高度、纸面下划线、朱红键盘焦点和减少动态偏好；页面不再重复这些可访问性与状态规则。
- 页面继续决定字段在海报、档案、案卷或时间线中的位置和节奏；共享原语不提供默认圆角卡片、蓝色焦点或整页表单网格，避免重新工业化。
- 展示标题输入可以显式选择展示字体；评分、日期、搜索命令等拥有独立交互语义的控件保留专用原语，不为组件数量最少而强行归并。

## ADR-023：完整课程事实是唯一来源，首页只消费可验证的轻量投影

**状态：接受。**

- `course-data.json` 继续保存完整 Course—Section—Meeting 发布事实；`course-core.json` 只能由同一生成流程从完整事实投影，不成为第二套可手工维护的数据源。
- 轻量投影保留全部 schedule 稳定 ID、学期、课程、教师、星期、节次、有效周、时间文本和地点，允许首页恢复既有本机课表并计算今天/未来安排和当前时段空教室；课程详情、教学班比较、专业课程关系和班级导入只使用按需加载的完整事实。
- CI 必须逐条对比轻量投影与完整时段的首页字段，并约束首屏文件不高于 750,000 字节。首页不得预取完整索引；只有进入课程库、课表、空教室、班级设置、全站课程搜索或课程详情时才加载，失败时保留今日学习台并明确重试。

## ADR-024：生产静态输出通过白名单网关提供

**状态：接受。**

- `npm start`、Docker 运行镜像和浏览器发布门禁统一启动 `server.mjs`；vinext 内部服务器只绑定 `127.0.0.1` 的独立端口，外部请求由同进程网关接收。
- 网关只从 `dist/client` 提供 `/assets/`、`/data/`、`/images/`、`/.well-known/` 与明确列出的根文件；解码失败、NUL、目录穿越、非文件和未列入路径都不会进入静态读取，其余请求代理给 vinext。
- 哈希构建资产使用一年不可变缓存，数据使用短期缓存与 stale-while-revalidate；全部静态响应带 `nosniff`。CI 在生产构建后真实启动网关，验证页面、JS/CSS、轻量/完整课程数据、HEAD、404 和源码不暴露，再执行完整 Playwright 门禁。

## ADR-025：长列表先用服务端边界与有界渲染，虚拟化必须有页面证据

**状态：接受。**

- 资料、教师、评价、社区、评论和通知继续使用服务端分页或游标作为数据与 DOM 上界；不能为了视觉连续性一次返回无界记录。
- 本地完整课程事实需要离线可搜索，因此课程选择器在当前学期内先按课程建立一次索引，再以 40 门为渲染窗口，每次追加 40 门；筛选条件变化必须重置窗口，不能对每张卡重复扫描全部时段。
- 当前有界列表不引入 DOM 虚拟化。只有 staging 证据表明既有上界仍造成可测量的 INP、内存或滚动问题时才采用，并必须同时保留键盘顺序、焦点恢复、读屏列表语义和搜索结果计数。

## ADR-026：小影异常在服务边界转换为稳定公共错误

**状态：接受。**

- HTTP 路由、校园服务适配器和任务执行器可以在服务内部保留异常类型与错误码，但页面、任务结果和审计不得消费原始 `error.message`。
- 公共响应只从审核过的 HTTP、配对、供应方和任务错误映射生成固定文案；未知异常统一失败关闭。JSON 解析错误在读取边界丢弃正文片段后再进入公共映射。
- 审计只保存任务身份、类型、状态、完成时间和稳定错误码，不保存异常原文、第三方响应、请求正文或凭据字段路径。新增错误类型必须先进入白名单映射和泄漏回归，不能在调用点临时直传文案。

## ADR-027：第三方写入的过期租约必须人工核对，不能自动重放

**状态：接受。**

- 空位检查、定时预约和预约守护只有取得 SQLite 原子租约后才调用适配器，完成更新必须匹配随机租约令牌；租约让重启恢复和并发 claim 可验证，但不假装第三方支持分布式事务。
- 只读空位检查可在租约到期后重领。预约或取消可能已在第三方生效而本地未落盘，过期后必须进入 `review_required`/`paused`、发送去重通知并等待用户核对，不允许直接改回待执行状态。
- 预约/取消确认以用户和幂等键摘要建立 30 天持久执行账本，并把键绑定任务类型/载荷摘要；已完成结果跨重启回放，同键异载荷冲突，执行中断转人工核对。预览只提供短期授权上下文，重启丢失时失败关闭并要求重新预览。

## ADR-028：生产邀请码是有界批次，不是长期共享口令

**状态：接受。**

- 正式小影必须同时配置至少 12 位随机邀请码和 1—500 次批次上限；缺少任一项都拒绝启动。仓库只提供变量名和无真实值示例，真实配置放在 600 权限环境文件。
- 邀请码只以加盐哈希保存，使用次数在 SQLite 写事务中通过 `use_count < max_uses` 条件原子增加；不能依赖事务外的先查后写，也不允许 `NULL` 表示无限使用。
- 服务启动时同码只更新上限并保留累计次数；换码时替换哈希、重置新批次计数并立即废止旧码。扩大人数通过显式调整批次配额或轮换新码完成，不能恢复无上限共享码。

## ADR-029：CSP 由实际生成文档的服务持有，Caddy 不覆盖

**状态：接受。**

- 主站网关为每个文档请求生成独立 18 字节随机 nonce，把同一策略传给 vinext 和浏览器；vinext 负责把 nonce 写入其生成的 RSC/模块内联脚本，`script-src` 不使用 `unsafe-inline`。网关直接提供的静态文件采用不能执行活动内容的独立策略。
- 小影是静态 HTML 控制台，服务启动时按完成子路径替换后的实际脚本、样式块和样式属性计算 SHA-256；策略仅允许精确哈希。不能手工维护会与页面漂移的哈希列表，也不能让上层代理追加更宽松策略。
- 主站 React/dnd-kit 仍依赖运行时样式属性，因此例外只放在 `style-src-attr`，不扩展到 `style-src` 或 `script-src`。未来移除该依赖后再收紧属性策略；任何新增内联脚本必须先通过生产文档 nonce 回归。

## ADR-030：正式应用只在主域名 HTTPS 来源提供

**状态：接受。**

- `dufesh.cn` 是唯一正式应用来源；`www` 和公开 IP 只做 308 规范化跳转并保留路径/查询，不能导入应用代理、认证 API、资料文件或小影。
- HSTS 只对域名客户端生效，不能替代 IP 明文站点的显式关闭。发布门禁必须分别请求主域名、`www` 和 IP，验证一次跳转后落在 `https://dufesh.cn`，且 IP 响应不设置会话 Cookie、不返回应用正文。

## ADR-031：没有可信修复时移除图片解析能力，而不是伪造补丁

**状态：接受。**

- vinext 只在构建期为本地静态 import 和图片 metadata 读取尺寸；当前产品图片均能以 public URL 和显式尺寸表达，因此不需要在构建机或生产镜像保留通用图片解析器。
- 根依赖提供项目内同名失败关闭包，并用 npm `$image-size` override 让 vinext 去重到该包。替代包不识别任何格式、不读取文件，所有调用立即抛出固定错误；版本后缀明确标识为项目隔离实现，不冒充官方发布。
- CI 拒绝 `app/` 本地图片 import 与图片 metadata 文件，避免开发者误以为尺寸探测仍可用。上游出现修复版时，必须先核对公告范围，并在干净安装、恶意样本、生产构建、浏览器和审计全部通过后才能移除隔离层。

## ADR-032：高风险 API 配额由权威数据存储原子裁决

**状态：接受。**

- auth-api 的通用高吞吐读写继续使用进程内有界令牌桶抵挡突发；凭据、重置、验证、上传、社区写入/互动/举报、教师评价和管理员敏感动作使用 PostgreSQL 共享令牌桶，不能因重启、扩容或轮转实例恢复配额。
- 桶身份由操作作用域和已有 HMAC-SHA256 摘要组成，数据库不保存原始 IP、账号、会话或用户标识。消费函数用行锁完成补充与扣减，拒绝请求也更新最后访问时间，避免活跃攻击桶被清理后重置。
- 生产入口必须显式把持久存储注入限流器；数据库无法给出布尔裁决时返回服务不可用，不允许自动退回单机内存。闲置桶只在完全补满所需最长时段之后由受控清理任务删除。
- 小影保持独立故障域：邀请码与公开配对入口使用现有 SQLite 持久卷和 `BEGIN IMMEDIATE` 固定窗口，IP 先由小影主密钥做 HMAC。反向代理链只信任最靠近服务端的转发地址，不能让客户端伪造最左侧地址换桶。

## ADR-033：第三方授权码和会话只允许经过逐跳校验的 HTTPS

**状态：接受。**

- TraceInt 授权码交换、返回页和 GraphQL 必须全部使用 HTTPS；官方 HTTP 端点即使仍可访问也不作为兼容降级路径。内置协议和站长版本化覆盖使用同一限制，旧配置含 HTTP 时启动失败关闭。
- 手工重定向的每一跳必须在发请求前同时检查 HTTPS 和官方域名，不能只验证初始地址或最终地址。发现明文或非官方跳转时，不发送已收集 Cookie，并返回稳定公共错误。
- 上游 HTTPS 能力必须在 staging 真实授权前再次探测；若未来 HTTPS 失效，暂停真实连接而不是恢复明文交换。

## ADR-034：备份只有完成隔离恢复和业务不变量检查后才算可用

**状态：接受。**

- `pg_restore --list` 只证明归档目录可读，不构成恢复证据。演练必须校验独立 checksum 与备份新鲜度，在同一 PostgreSQL 版本的唯一临时数据库完整恢复，并检查迁移数、未验证约束和发布所需关键表。
- 临时库名只能由固定前缀、UTC 时间和进程号生成，绝不能接收生产库名；无论成功、校验失败或超出 RTO，退出陷阱都只删除该临时库。演练不得修改生产库或依赖覆盖式 restore。
- 恢复时长必须与明确 RTO 上限比较，结果进入运维日志。定期演练不能替代异地主机/对象存储副本；没有异地副本时 SEC-009 继续保持未完全关闭。

## ADR-035：发布工作流第三方 Action 使用不可变引用与最小权限

**状态：接受。**

- 第三方 GitHub Action 必须锁定到已核对发布版本对应的完整提交 SHA，旁边保留可读版本注释；不得直接使用可移动的主版本标签。升级前核对发布说明、Node 运行时和 runner 最低版本，并由基础设施合同锁定引用。
- checkout 默认关闭凭据持久化；只有确需完整提交历史的秘密扫描使用 `fetch-depth: 0`。普通质量和构建作业不获得写权限，CodeQL 只增加安全结果写入，秘密扫描关闭评论和制品上传。
- 密钥扫描必须覆盖完整 Git 历史，不能只检查当前工作树。工作流存在和本地 YAML/合同通过不等于扫描通过；只有受信任 GitHub runner 的实际结果才能满足发布检查表。

## ADR-036：生产环境模板必须以空秘密失败关闭

**状态：接受。**

- 仓库按 PostgreSQL、auth-api、小影和备份保存分域模板；秘密字段只保留变量名并使用空值，不提供长度或格式可能恰好通过校验的 `replace-with-*` 示例。真实值只进入 600 权限服务器文件或密钥管理服务。
- Compose 固定的端口、路径和非秘密运行参数不在秘密模板重复维护；自动合同从服务源码提取环境变量，并要求每个读取项由模板或 Compose 明确持有。新增变量必须同时指定归属，否则 CI 失败。
- 未取得真实第三方凭据时正式模板保持相应能力关闭。微信 mock 只用于受控开发或 staging，不是 real 模式的替代品；生产模板不得因为审核中而默认扩大测试授权面。

## ADR-037：release 目录、镜像和回滚使用同一个完整 Git SHA

**状态：接受。**

- 主站、auth-api 和小影的正式镜像标签必须等于发布提交的完整 Git SHA，并与 release 目录名、镜像 ID/RepoDigest 和发布记录绑定；`latest` 只保留本地兼容默认值，不构成正式版本身份。
- 原子切换只允许把 `/srv/apps/dufesh/current` 指向固定 releases 目录下已核对的目标。启动和回滚都显式传入该目录对应的 `DUFESH_IMAGE_TAG`，避免“目录已回滚、容器仍使用新镜像”。
- 应用回滚不运行旧迁移器，也不覆盖恢复生产数据库；所有迁移在发布前必须向后兼容。不能证明旧应用兼容当前 schema 时停止回滚并使用预审查的前滚修复。

## ADR-038：账号邮件统一经过失败关闭的 SMTP 适配边界

**状态：接受。**

- 密码重置与邮箱验证只允许 `disabled`、本地 `response` 或正式 `smtp` 三种显式模式；生产禁止把令牌写入 HTTP 响应，选择 SMTP 却缺主机、凭据、发件地址或投递适配器时拒绝启动。
- SMTP 连接至少使用 TLS 1.2 并验证证书；465 使用隐式 TLS，587 等非加密入口强制 STARTTLS。消息只包含受校验的收件地址、固定主题和纯文本一次性令牌，禁用文件、URL 与附件内容读取，避免把用户输入扩展为邮件内容能力。
- 密码重置无论账号是否存在或投递是否成功都保持相同 202 响应，SMTP 网络调用不阻塞 HTTP 响应，避免通过状态、正文或远端投递延迟枚举账号；真实投递健康由 staging 冒烟与受限运维监控判断，日志不得包含邮箱、令牌、SMTP 密码或上游异常正文。

## ADR-039：社区个人主页是公开内容投影，不是账号资料页

**状态：接受。**

- 公开主页以现有稳定用户 UUID 定位，只投影用户名、显示名称、规范化头像、加入月份，以及仍处于 `published` 状态的公开主题和公开主题下回复；邮箱、校园账号、角色、课表、日程、收藏、登录时间和仅链接内容不进入响应。
- 主题与回复分别使用有界 keyset 游标，避免一次加载完整历史。停用或注销账号、任一方向屏蔽均统一按档案不可用处理，不能通过个人主页绕过社区列表和详情已有的可见性边界。
- 作者徽章是进入公开主页的统一入口。个人主页不提供任意个人简介、外链或富文本字段，后续如扩展必须重新完成隐私、链接净化、滥用和账号注销审查。

## ADR-040：社区热议使用可解释的快照游标，不建立黑箱用户分

**状态：接受。**

- 热议排序只计算主题收到的真实赞同、仍为 `published` 的回复与主题 14 天内的新鲜度，权重依次为 2、3 和每日递减的 14—0 分；不采集浏览轨迹、不建立用户画像，也不按作者身份、账号等级或管理员选择加权。
- 第一页取得排名时点，后续游标携带该时点、热议分数、发布时间与 UUID，并按这四个事实继续 keyset 分页。新互动不会进入已经开始的一轮翻页；主动刷新或重新切换热议才取得新时点。取消赞同、删除/隐藏回复属于治理或用户主动撤回，允许从后续读取中移除其贡献。
- 时间游标和热议游标使用不同精确结构，不能跨排序复用；服务端拒绝额外字段、非法时间、非法 UUID、非十进制或超长分数。前端只解释影响热议的三类公开信号，不显示容易诱导刷榜的原始分数。
