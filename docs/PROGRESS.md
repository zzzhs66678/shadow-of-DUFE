- **已验证**：功能已实现，并有自动化或明确人工验收证据。

- **已实现但测试失败**：代码存在，但当前不能作为可交付能力。

## M1 已验证切片：账号本地数据隔离

- 旧版 `dufesh:student-profile:v2` 只迁移到匿名作用域，不会自动进入任一登录账号。
- 匿名数据和每个 `user_id` 使用不同本地键；同步基线元数据也按用户分区。
- 退出或注销后清除当前账号的本地缓存与同步元数据，再恢复匿名作用域；不会显示或上传前一账号的数据。
- 登录后检测到匿名数据时只显示显式选择，“导入当前账号”前不会合并；“暂不导入”保留匿名数据。
- 本地 auth API 缺失或返回非成功状态时，账户中心进入匿名/离线状态，不再永久停在加载中。
- CI 已加入 auth-api 安装、生产依赖审计、10 项服务测试，以及个人存储/同步回归。
- 验证：账号存储/同步 9/9、体验与基础设施合计 22/22、auth-api 10/10、构建与 SSR 2/2；390px 浏览器页面无横向溢出。

## M1 已验证切片：管理员加密与 MFA 数据底座

- 新增增量迁移 `0008_admin_security.sql`：服务端角色、TOTP 因子、单次恢复码、绑定基础会话的短期提升会话和 append-only 管理审计事件。
- TOTP 按 RFC 6238 的 SHA-1、6 位、30 秒与 ±1 时间步验证；匹配后的时间步将由数据库条件更新原子消费，阻断并发重放。密钥使用 AES-256-GCM，加密 AAD 绑定因子 ID、用户 ID 与用途；key ID/keyring 支持逐步轮换。
- 恢复码由 128 位随机数生成，明文只在初始化时显示一次，数据库只存独立 `AUTH_ADMIN_RECOVERY_PEPPER` 的域分离 HMAC 摘要，不复用普通会话 pepper。
- 管理员默认关闭，只能用 `npm run admin:bootstrap -- <username-or-email>` 将明确的已有活跃账号初始化；不会自动提升首个注册者。重复初始化必须显式 `--rotate`，且会撤销该账号全部基础/提升会话并写系统审计。
- 验证：auth-api 26/26，包含 RFC 向量、密文不含明文、AAD 绑定、TOTP 时间窗/重放、恢复码规范化与 pepper 隔离、配置失败关闭；真实 PostgreSQL 迁移/原子并发、运行期数据库角色拆分、管理 API 与界面尚未完成，本切片未部署。

## M1 已验证切片：管理员 RBAC 与提升会话 API

- `/api/admin/session`、`/elevation`、`/overview`、`/users`、`/audit` 和用户状态写入均由服务端实时角色授权；匿名返回 401，普通用户在任何管理查询前返回统一 403，不根据对象是否存在产生差异。
- TOTP 或恢复码成功后签发独立 `__Host-`、HttpOnly、Secure、SameSite=Strict 提升 Cookie，固定最长 10 分钟且绑定当前基础会话；另一会话携带同一 Cookie 仍被拒绝。退出、密码重置、当前设备撤销、账号禁用与删除均清除或使提升失效。
- TOTP 时间步和恢复码在创建提升会话的同一事务中条件消费；相同 TOTP 时间步或恢复码只能成功一次。MFA 按 IP+用户+基础会话独立限流，Origin 缺失或不可信时不读取 MFA 数据。
- 用户列表只返回掩码邮箱和必要状态；账号禁用、全部会话撤销、提升撤销与包含脱敏前后状态/原因的审计事件同事务提交。写操作进入事务后再次验证管理员、基础会话与提升会话，避免授权检查后的竞态。
- 迁移器已支持创建独立 `AUTH_DB_USER` 非 owner 运行角色；运行角色可读写业务表，但不能更新/删除/截断 `admin_audit_events`，也不能访问 `schema_migrations`。Caddy 为 `/api/admin/*` 增加 no-store、noindex 同源代理。

## M0 审计结论

### 发布阻断

1. 退出账号后本地 `saved` 未按账号隔离；同浏览器 B 账号可能把 A 的本地数据合并上传。
2. 现有账号服务只有 disabled/mock OAuth，没有普通用户可用的真实注册登录。
3. 没有服务端 RBAC、管理员 MFA、管理 API 和管理员审计。
4. 资料清单没有进入真实搜索路径，点击课程会进入教学班选择。
5. 不存在 `teacher_id`、社区、通知、举报和审核数据模型。
6. TraceInt 的授权码与 Cookie 交换当前使用明文 HTTP，需要确认上游能力并消除或隔离链路风险。
7. 关键 UI 测试以源码正则为主，不能证明键盘、焦点、移动交互和权限真实可用。

### 前端与体验风险

- `DufeHubV2.tsx` 超过 5,000 行，页面、数据、弹层与路由耦合。
- 三层 CSS 含多个历史覆盖段；当前约 248KB 客户端 CSS，需在 M5 收敛。
- 首页启动即读取约 3.07MB 课程 JSON 与约 259KB 资料清单，需在 M6 拆成轻量入口数据。
- 搜索文案承诺方向键和 Enter，但现有实现只有 Escape。
- 多个弹层缺完整焦点锁定；隐藏抽屉仍可能留在可访问树。
- 部分手机触控目标只有 34–40px；今日主 CTA 在 390×844 首屏以下。

### 教师工作簿审计

- 源文件：用户提供的 `教师评价（学长学姐）.xlsx`，未复制进仓库。
- 1 个工作表，38 位教师，2 个学院，135 条非空历史评论；5 位教师没有评论。
- 未发现手机号、身份证号、邮箱、URL 或明显社交账号格式。
- 发现至少一条直接辱骂，以及若干无法核验的个人化或考核结论；原始内容不得直接上线。
- 导入时必须增加来源、批次、内容摘要、脱敏/审核状态，并统一标记为“历史整理内容”。
