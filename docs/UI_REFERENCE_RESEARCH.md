# DUFESH UI / UX 参考研究

更新时间：2026-07-22

## 研究目标

寻找可迁移到 DUFESH 的成熟交互模式，而不是复制某个网站的视觉外壳。重点覆盖：立体教学楼空教室、游戏化选课、个性化首次设置、多页面导航、手机与电脑响应式、课表生成与导出。

## 一、立体教学楼与空教室

### 1. Mappedin：楼栋和楼层选择

- 参考：https://developer.mappedin.com/web-sdk/level-selection
- 可借鉴：建筑/楼层分层模型、明确的当前楼层状态、切换楼层时保持上下文、点击地图实体进入详情。
- 不照搬：DUFESH 没有真实建筑平面图，不需要昂贵的室内导航 SDK，也不需要旋转、缩放和路线规划。

### 2. Robin Office Map：实时空闲状态

- 参考：https://support.robinpowered.com/hc/en-us/articles/360014882672-How-to-use-the-office-map-kiosk-status-board
- 可借鉴：空闲/占用/即将占用状态图例、按时间切换、点击房间出现信息卡、搜索房间、显示下一次占用时间。
- 改造：我们的教室不可预订，只提供“现在是否空闲、下一节何时有课、还能自习多久”。

### 3. Exploded axonometric / 建筑爆炸图

- 可借鉴：楼层上下分离的轴测截面、纵向贯穿关系、选中楼层向外抽出、未选楼层降低透明度。
- 最终做法：不用真实平面图。每栋楼生成风格化 SVG 建筑截面，每层包含若干教室窗口；空教室亮起，忙碌教室变暗，即将上课使用倒计时标识。

### 地图最终交互

1. 页面顶部横向切换五栋教学楼。
2. 日期、当前节次和四大时段时间轴保持在顶部或底部固定区域。
3. 主体是一栋完整立体截面，可同时看到全部楼层。
4. 点击某层，楼层轻微向外抽出并展开该层教室。
5. 点击教室出现底部抽屉/侧边卡片，显示当前状态、下一节课程和可用时长。
6. 状态不能只依赖红绿颜色，同时使用亮度、图标和文字，照顾色觉差异。

## 二、游戏化选课与个人课表

### 1. MOBA 角色选择流程

- Riot 对选人界面的原则：https://www.leagueoflegends.com/en-us/news/dev/client-cleanup-next-stop-champ-select/
- 可借鉴：可搜索的角色池、选中对象的聚焦展示、当前阵容槽位、确认反馈、明确的冲突/不可用状态。
- 关键教训：Riot 也强调响应速度、低内存和减少低价值动画。DUFESH 的趣味性不能牺牲手机性能和选课效率。

### 2. Linear：列表、看板、快速预览和撤销

- 列表/看板切换：https://linear.app/docs/board-layout
- 快速预览：https://linear.app/docs/peek
- 统一动作与撤销：https://linear.app/docs/conceptual-model
- 可借鉴：同一数据支持普通列表和游戏化卡牌两种视图；点击卡片在侧栏预览；所有添加、删除、替换操作提供撤销；电脑提供键盘搜索，手机仍使用明显按钮。

### 3. Timetable Generator / SchedBuilder

- 参考：https://timetablegenerator.app/timetable-generator/
- 参考：https://schedbuilder.com/
- 可借鉴：添加课程后实时刷新周课表、浏览器自动保存、云端同步、图片/PDF/ICS 等多格式导出、冲突即时提示。

### 选课最终交互

1. 初始专业/班级课程自动成为“默认阵容”。
2. 全校课程进入“课程池”，支持课程、教师、专业、时间筛选和模糊搜索。
3. 课程卡只显示课程、教师、时间、教室；使用课程简称/首字作为识别图形，不使用人物素材。
4. 点击“加入阵容”时，卡片以短动画进入底部阵容栏，同时课表对应时间格亮起。
5. 点击“换课”直接列出同名课程的其他教师、时间和教室；一键替换，并支持撤销。
6. 时间冲突不禁止添加，以叠放卡片和警示边框显示。
7. 手机以点击为主；桌面额外提供拖拽，但拖拽绝不是唯一方式。
8. 提供“游戏化卡牌 / 快速列表”切换，满足不同用户。

## 三、首次个性化设置

### 参考思路

- Pinterest 兴趣选择用少量选择解决冷启动：https://omegapoint.systems/case-studies/pinterest-interest-picker
- Spotify 允许用户查看并调整个性化偏好：https://newsroom.spotify.com/2026-03-13/taste-profile-beta-announcement/

### 最终交互

- 弹窗不出现文本输入，只使用网站数据的级联选择：入学年份 -> 学院 -> 专业 -> 班级。
- 开头先解释收益：“生成你的课程、教师、资料入口与个人课表”。
- 每一步立即显示选择结果和简短进度，不用长篇教程。
- 始终提供“跳过”；以后在“我的”中可查看并修改系统对自己的专业/班级理解。
- 完成后立即展示第一份个人课表，形成首次使用的即时成果。

## 四、跨设备导航与多页面结构

### 1. Carbon UI Shell

- 参考：https://v10.carbondesignsystem.com/components/UI-shell-header/usage/
- 可借鉴：桌面持续存在的横向顶栏；左侧品牌、中部产品级导航、右侧全局动作；窄屏时导航收起。

### 2. Material 自适应导航

- 手机底部导航：https://m2.material.io/components/bottom-navigation/
- 中/大屏导航轨：https://m2.material.io/components/navigation-rail
- 可借鉴：手机使用 3-5 个底部主入口；屏幕变宽后转换为顶栏或侧栏；页面内相关内容再用标签，不重复主导航。

### DUFESH 最终壳层

- 桌面：顶部横向导航 `首页 / 课程与资料 / 我的课表 / 空教室 / 校园服务`，右侧为全局搜索、学期/昼夜、用户。
- 手机：紧凑顶部栏 + 底部 `首页 / 课程 / 课表 / 空教室 / 我的`。
- 页面内二级导航使用横向标签；不让整个网站变成无限左右滑动，也不让所有功能堆成长页面。
- 桌面课程详情使用右侧预览；手机使用底部抽屉或独立详情页。

## 五、视觉方向

- 保留首版的米白纸张、深色正文和克制红色，作为与普通校园门户不同的品牌识别。
- 加入现代产品化层：精确网格、轻量卡片、状态色、细腻动效和清晰导航。
- 游戏化页面可以更深色、更沉浸，但仍与全站字体、间距和红色强调保持同一设计系统。
- 白天/上学期：温暖米白、墨色、朱红、浅青状态色。
- 夜间/下学期：深墨蓝/炭黑、暖白文字、低饱和红与蓝绿状态色。
- 动效建议 160-260ms，支持 `prefers-reduced-motion`；不加入强制音效、粒子背景或长时间过场。

## 六、明确不采用

- 不复制 Dota、英雄联盟或其他游戏的角色、美术、名称、图标和音效。
- 不使用需要高性能 GPU 的重型 WebGL 建筑模型作为主要功能。
- 不把拖拽作为手机上的必要操作。
- 不用“稀有度、战力、星级”评价课程或教师。
- 不展示教材/资料的空占位模块。
- 不为了“页面丰富”堆无关统计、假数据和大段装饰文案。
- 不让用户在手机上进行精细旋转、缩放或难以点击的小目标操作。

## 七、设计验收标准

- 360px 宽手机与微信内置浏览器可以单手完成主要任务。
- 用户在三次点击内从首页到达课程资料或当前空教室。
- 首次设置可跳过，并能在一分钟内生成个人课表。
- 添加/替换课程后，阵容与周课表立即同步并可撤销。
- 一栋楼的所有楼层在手机一屏或接近一屏内形成完整视觉关系。
- 无教材/资料时不出现空框。
- 首屏不依赖大图，弱网络下仍优先显示核心数据。
