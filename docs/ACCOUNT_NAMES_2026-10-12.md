## 最终行为

- 登录用户名为 1–24 个 Unicode 码点，仍使用现有 NFKC、首尾空白清理和 JavaScript 小写比较规则，数据库唯一约束保持。旧账号和短密码登录不被这次改动强制升级。
- 新注册及重置密码改为 8–128 个 Unicode 码点，这是用户明确选择的产品策略。密码仍原样交给 Argon2id，不静默截断；常见弱口令和不少于三个码点的账号、邮箱提示检查保留。一两个字符的用户名不再导致大量正常密码被误拒。
- 注册可选择公开昵称 `momo`，内部登录用户名仍须唯一。公开展示可在 `momo` 与自己的名字之间切换，自己的名字持续保留，不因使用 `momo` 释放名额。初始注册选择不计为一次切换；首次切换不限，之后每次实际切换须间隔七天，同模式重试不重置时间。
- 非 `momo` 的保留名字由 PostgreSQL 统一执行 NFKC、完整 ECMAScript 首尾空白清理和 PostgreSQL `lower` 比较并保持唯一，含停用、删除账号。公开名字大小写规则与旧 JavaScript 登录标识规则分别说明，不声称希腊字母等边界完全相同。
- 改登录用户名或自己的名字须提交申请，申请不会立即改名。管理员必须在有效基础会话与有效 MFA 提升会话中批准或拒绝；批准时重新核对申请快照、账号状态、唯一约束与会话有效期。
- 东财墙的帖子、回复、公开主页、收藏、屏蔽与通知使用相同公开展示投影，`momo` 带小猫标志。账号 UUID、帖子归属、草稿作用域、屏蔽关系和通知收件人保持独立；`@提及` 继续使用唯一登录用户名，不按重复的 `momo` 昵称群发通知。
- 注册表单不提前堆叠用户名或密码规则提示，提交时仍校验并给出固定、可理解的错误。账号页面、管理员资料、隐私与条款中的相关“校园账号”文案改为“学号”；字段仍选填，未经验证的学号不作为学生身份凭据。

8 字符下限比原来的 15 字符下限更宽松，允许出现更短、更容易猜测的密码；Argon2id、弱口令检查与服务端限流继续降低风险，不能把这些防护当作长密码的等价替代。注册时验证一次邮箱也不代表普通账号登录已开启 MFA。管理员 MFA 保持原有独立机制。

## 回滚边界

优先只回退 app，保持理解 `name_mode` 和审核保护的新 auth 与 0030 数据库。必须核对旧 app 与新 auth 的兼容性，尤其旧表单的显示名回显与学号保存；新 auth 已识别旧表单回显的 momo，不因此释放保留名字或擅自改名。

若把 auth 一并退回 `2a470c0`，0030 更新保护仍会拒绝旧 profile 或 OAuth 的真实改名；旧密码登录可以继续使用。但旧 auth 不识别 `name_mode`，公开接口会直接读出保留的 `display_name`，将正在使用 momo 的用户展示成自己的名字。数据库审核保护不能修补这种旧响应投影。回退前必须暂停受影响的东财墙/教师讨论等公开作者接口，或明确采用保持新 auth 的回退方式，不能声称旧 auth 回退同时保留 momo 展示隐私。旧 OAuth 昵称不同的自动更新也可能被保护拒绝，不能默认其旧流程完全可用。

保留追加迁移、申请记录和审计，不为普通回退删除新字段或数据库表。生产全库恢复会覆盖发布后的新用户与业务写入，属于高风险操作，须单独核实恢复时间点及数据损失并取得人工确认。本轮未执行生产二进制回滚或生产全库恢复。
