# 东财之影安全审计

最后更新：2026-08-09

## 1. 范围与信任边界

本轮覆盖主站、auth-api、PostgreSQL、小影、Caddy、静态资料目录、浏览器本地数据、文件上传和第三方校园服务。主要攻击者包括匿名机器人、恶意注册用户、骚扰/刷评用户、被盗会话持有者、恶意上传者、被盗管理员，以及被劫持或协议变化的第三方服务。

核心资产：账号与会话、课表/日程/任务、教师与社区内容、第三方授权包、管理员权限、审计记录和备份。

## 2. 已存在并已验证的控制

- 站内会话使用 32 字节随机令牌，数据库只保存带 pepper 的 HMAC 摘要。
- Cookie 使用 `__Host-`、Secure、HttpOnly、SameSite=Lax，无 Domain。
- OAuth state 与浏览器绑定、10 分钟过期且原子消费，回调重放被拒绝。
- 个人同步写入有同源检查、512KB 上限、字段校验、逐用户版本、幂等 mutation 和事务咨询锁。
- PostgreSQL 与应用服务不映射公网端口；容器具备资源限制和日志轮转。
- 小影敏感连接使用 AES-256-GCM，主密钥与数据库分离。
- 小影 HTTP 和任务执行器通过同一公共错误映射返回稳定错误码与固定文案；未知异常、第三方响应、请求片段和凭据字段路径不会进入页面、任务结果或审计记录。Malformed JSON 与模拟上游私有会话异常均有泄漏回归。
- 小影后台读取与写入任务使用带随机令牌和到期时间的 SQLite 原子租约；旧令牌不能完成写回。只读租约可重领，第三方写入结果不确定时转入人工核对而不自动重放。预约/取消确认使用持久化执行账本，幂等键只存摘要、同键绑定请求摘要、结果跨重启回放且 30 天后清理；短期预览重启后失败关闭。
- 小影生产邀请码必须同时配置至少 12 位随机码和 1—500 次使用上限；任一缺失都会拒绝启动。SQLite 事务以 `use_count < max_uses` 条件原子消费，已有无限默认码在启动时升级为有界配额，轮换码会重置新批次计数并废止旧码。
- 生产前端只把 vinext 绑定在回环端口；外部网关仅从 `dist/client` 白名单提供哈希资产、数据、图片、`.well-known` 和明确根文件，拒绝解码异常、NUL、目录穿越和源码路径，并为静态响应设置 `nosniff`。
- 主站把 vinext 的构建期 `image-size` 依赖覆盖为仓库内失败关闭包：不再安装通告覆盖的 ICNS/JXL/HEIF 解析器，所有探测请求立即抛出固定错误。主站、auth-api 与小影生产依赖审计当前均为 high/critical 0；仍须由 Linux PR CI 和 staging 镜像复核。
- 资料接口为公开只读面，查询字段做 NFKC 规范化和长度限制，分页每次最多 60 条；响应使用稳定 `material_id` 与清单内既有同源 URL，不接受任意文件路径，也不把内部搜索字段返回浏览器。
- 社区公开读取接口只接受结构校验后的 UUID、有界游标与每页最多 30 条；SQL 全部参数化。双向屏蔽关系从公开列表和详情隔离，已删除/屏蔽评论只保留线程墓碑，不返回正文和作者，降级地址固定为本站路径。
- 社区主题/评论写入要求可信 Origin、有效会话、用户与 IP 双维度专项限流；请求严格白名单、NFKC 和纯文本长度/控制字符校验，编辑删除使用乐观版本。数据库事务复核账号制裁、作者归属和目标可用性，并把旧正文写入不可变历史后再更新或软删除。
- 社区互动使用幂等 `PUT`/`DELETE` 和数据库唯一键；写入前复核内容、封禁与双向屏蔽，取消点赞不返回不可见目标计数。拉黑事务清理双方遗留点赞、拉黑者收藏和来自对方的旧通知。举报使用独立账号+IP 低频限流、固定原因码和部分唯一索引，重复开放举报不改写首份证据。
- 回复和提及通知与内容写入共用事务，唯一键防重；自己、失活账号和双向屏蔽目标不接收通知。通知读取、已读和隐藏 SQL 始终绑定当前收件人；软删除会同步清空通知正文并切换本站降级路径，账号注销后的去标识化 actor UUID 不进入响应。
- 管理员社区治理沿用角色、基础会话与短期 MFA 提升三层授权，并在每个治理事务内重新验证，撤权后不会继续读取举报或修改目标。请求使用可信 Origin、字段白名单和动作—目标状态矩阵；隐藏内容必须恢复或删除、生效制裁必须解封后才能结案。案件动作同步写社区 append-only 记录与全局管理员审计，内容状态、制裁、举报结案、旧通知脱敏和作者通知原子提交；写入成功后的列表刷新故障不会被呈现为写操作失败。
- 举报在创建事务中保存不可变标题、正文、作者标签与取证时间快照；审核队列不回读可变正文作为首份证据。数据库触发器拒绝修改快照，重复开放举报返回原证据。
- 社区与审核界面不持久化会话令牌；通知降级地址再次做本站路径限制。举报/治理弹层提供焦点陷阱、滚动锁、Escape 关闭和焦点恢复，减少键盘用户误操作与背景操作风险。
- 教师/教材 dry-run 对输入文件设置 50MB 上限，错误 CSV 不包含评价正文并防止公式注入；联系方式在候选正文中先脱敏。导入批次、逐行证据、mutation 和历史评价候选对 auth runtime 完全撤权，教师目录与教材事实也撤销运行时写权限。
- 私有导入包拒绝写入 `public/`/`app/`，写入数据库前二次检查联系方式、摘要、正文长度和记录上限。数据库写入要求显式 `IMPORT_ALLOW_APPLY=true` 与独立无继承 importer 角色；事务 advisory lock、已应用文件部分唯一索引和 append-only mutation 共同约束重复/回滚。
- 历史评价候选列表和决定只能通过固定 `search_path` 的 SECURITY DEFINER 函数访问，函数内再次验证活动管理员、基础会话和短期 MFA elevation。批准、一次性不可变决定、公开评价和管理员审计同事务；审计失败整体回滚。importer 没有候选 UPDATE 或决定/公开评价写权限。
- 教师公开接口只接受 GET、有界 NFKC 查询、严格 UUID 和结构校验游标；SQL 参数化且每页最多 50 位教师/30 条评价。响应不含私有候选、原文摘要、来源 digest、导入证据或内部身份状态，只返回 `published` 评价；历史评价评分始终为 `null`。
- 用户教师评价写入只信任服务端会话作者，不接受作者、评价 ID、状态或来源字段；要求可信 Origin、JSON、精确字段、用户/IP 专项限流和乐观版本。数据库部分唯一索引保证每个用户—教师最多一条活动评价，触发器复核正文摘要和评分；账号注销只允许内容不变的撤下与去标识化，不阻断注销也不让旧正文继续公开。

## 4. 实施要求

### 身份与会话

- Argon2id；统一登录错误；密码强度与泄漏密码策略；失败次数、退避和 IP+账号限流。
- 会话创建后轮换；密码重置、账号禁用和高风险管理操作撤销相关会话。
- 一次性令牌只存摘要，短 TTL，单次原子消费；日志中不出现邮箱完整值、Token 或密码。

### 权限与管理

- 每个管理 API 服务端检查角色与提升会话；不存在性与无权限响应不泄漏敏感对象。
- TOTP secret 加密保存，恢复码只存 hash；管理员操作写 append-only 日志。
- `/admin` noindex，普通用户无入口且直接访问始终被服务端拒绝。

### 输入、社区与上传

- 所有字段白名单校验、长度限制、Unicode 规范化、参数化 SQL；不接受任意对象 mass assignment。
- 账号资料、社区和管理员治理写入已按上述要求实现并通过 Mass Assignment、跨站 Origin、对象作用域或动作—目标矩阵测试；真实 PostgreSQL 权限与并发仍需复核。
- 默认纯文本；若支持富文本，只允许严格标签/属性白名单并净化 URL。
- 头像已通过 MIME 与魔数一致性、尺寸/像素/体积限制和服务端 WebP 重编码移除 EXIF；原图不落库。后续通用附件仍须检查扩展名、MIME 和魔数，并在隔离扫描后再公开。
- 点赞、举报、回复、登录和上传按账号、IP、设备与动作分别限流；唯一索引防重复。
- 社区数据库底座已把回复限制为两层，为点赞、收藏、提及、通知和开放举报加入唯一约束，并将编辑历史和治理动作设为 append-only；服务端对象级授权和输入净化已覆盖测试，真实 PostgreSQL 触发器/权限仍是发布门禁。
- 社区不可变记录不使用会在账号删除时回写的 actor/reporter 外键；只保留去标识化 UUID/必要标签快照，避免审计触发器阻断注销或级联丢失举报证据。通知降级地址限本站相对路径，举报、案件和动作目标由数据库触发器核对。
- `0012` 把举报时可见内容固化为不可变证据；staging 必须验证运行角色不能更新这些字段，并验证旧举报回填、重复举报、内容编辑/删除后的取证一致性。
- `0013`—`0015` 只允许稳定来源键映射教师；历史评价候选、决定与导入证据不向 auth runtime 开放直接表权限。staging 必须验证运行角色只能通过二次鉴权函数读取/决定候选，importer 只能调用未批准候选回滚函数，并验证同一文件并发 apply、approve/reject、用户评价写入和回滚竞态只有一个有效结果。

### 部署与恢复

- Caddy 安全头、HSTS、CSP nonce/hash、HTTPS 唯一入口；关闭或重定向明文 IP 站点。
- 构建后必须通过受限生产网关验证客户端 JS/CSS、水合、公开数据与源码拒绝；不得直接以 `vinext start` 替代仓库启动命令。
- 拆分数据库 owner/migrator/runtime/backup 角色；服务端只拿运行期最小权限。
- 加密异地备份、定期临时库完整恢复、记录 RPO/RTO；回滚不依赖未验证备份。
