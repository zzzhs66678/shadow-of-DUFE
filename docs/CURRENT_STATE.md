# 东财之影：当前状态

最后更新：2026-08-13

## 产品

- 名称：东财之影。
- 面向东北财经大学学生的课程、个人课表、空教室与学习资料入口，允许校外访问。
- 移动端和微信内置浏览器优先，同时适配电脑。
- 首页核心是“今日学习台”，集中展示下一节课、日程、作业截止时间、空教室和常用入口。

## 当前技术状态

- 前端：React + TypeScript + vinext。
- 课程数据由 Excel 离线生成完整 `public/data/course-data.json`，并同步生成首页轻量 `public/data/course-core.json`；两份文件来自同一生成器并携带同一个由最终 schedule 事实确定的 `catalogId`，课程、教学班、上课时段及既有 ID 关系不变。
- 未登录用户的个人档案、课表、日程和作业继续保存在浏览器 `localStorage`。账号中心、首次上传、后台同步和多设备冲突处理已经部署；正式微信登录仍在审核，因此普通用户暂时还不能启用云同步。
- 主站账号数据库底座已于 2026-07-30 部署为 PostgreSQL 17，运行在现有 ECS 的 Docker 私有网络中，不映射主机或公网 5432 端口。
- PostgreSQL 使用独立持久化数据卷，当前限制为 384MB 内存、50 个数据库连接、15 秒语句超时、3 秒锁超时和 30 秒空闲事务超时；慢于 500ms 的查询写入受轮转保护的容器日志。
- 已建立可重复执行并校验文件摘要的 SQL 迁移机制；首个迁移包含站内用户、外部授权身份、用户设备、站内会话和迁移记录五张基础表。站内会话表只保存随机令牌哈希。
- 独立账号 API 已部署在 Docker 私有网络，通过同域 `/api/auth/*` 由 Caddy 反向代理；容器限制为 128MB，2026-07-30 空载实测约 20MB。
- 账号 API 使用最多 10 条 PostgreSQL 连接，连接等待上限 3 秒、查询上限 10 秒；匿名设备最近访问时间最多每 5 分钟写入一次，避免高频刷新造成数据库行锁。
- `GET /api/auth/session` 已支持稳定匿名设备身份和登录状态读取，`POST /api/auth/logout` 已支持同源校验与服务端会话撤销。Cookie 使用 `__Host-` 前缀、`HttpOnly`、`Secure`、`SameSite=Lax`、全站路径且不设置 `Domain`。
- Cookie 中只保存 32 字节随机令牌，数据库只保存带独立服务端 pepper 的 HMAC-SHA256 摘要；pepper 仅存在于服务器 600 权限环境文件。
- 账号会话底座已在正式 HTTPS 环境完成并发状态读取，全部返回成功且匿名设备身份稳定；当前尚未开放任何用户可见的登录入口。
- 可替换的微信 OAuth 适配层已部署；审核期间使用仅限内部测试密钥访问的 mock 提供方，未在用户界面显示入口，无密钥访问正式站模拟授权接口返回 403。
- OAuth 登录事务使用 43 字符随机 `state` 和独立浏览器绑定 Cookie，数据库仅保存两者的 HMAC 摘要；事务 10 分钟过期且只能原子消费一次，回调重放会被拒绝。
- 模拟闭环已在正式 PostgreSQL 验收：首次授权建号、匿名设备绑定、签发站内会话、退出撤销、同一微信身份再次登录复用原用户、错误浏览器 Cookie 和旧回调拦截均通过。测试结束后用户、身份、会话、OAuth 事务和匿名设备记录均已清零。
- 2026-07-30 OAuth 版本再次完成正式 HTTPS 100 并发状态读取，全部成功且设备身份稳定，总耗时约 0.80 秒；账号 API 内存约 23MB，PostgreSQL 约 46MB。
- 个人云数据模型已于 2026-07-30 部署：覆盖档案、课表方案、具体教学时段、个人日程、课程任务、主题与教室偏好。所有可变记录都带逐用户递增版本和客户端更新时间，课表、日程与任务使用稳定客户端 ID 和软删除墓碑，支持后续幂等首次上传、增量同步与多设备冲突处理。
- 正式 PostgreSQL 已通过个人数据冒烟测试：同一教学班的多个教学时段分别保留、跨用户课表关系被数据库拒绝、账号删除会级联清理全部个人数据；测试数据在同一事务内完成清理。迁移脚本重复执行不会重复建表或改写既有迁移。
- 同域个人同步 API 已于 2026-07-30 部署：读写均要求有效站内会话，写请求额外校验可信 `Origin`、512KB 请求上限、逐字段数量/长度和逐用户版本。每次写入携带绑定请求内容的幂等 mutation ID，重复请求不会重复应用，旧版本写入返回最新快照而不覆盖。
- 浏览器已接入账号作用域的首次上传和后台同步：账号自己的本地缓存可与云端合并；未登录时的匿名数据必须由用户明确选择后才会导入账号。已有云数据会保留云端同 ID 记录，并合并账号本地独有方案、具体教学时段、日程与任务。后续采用账号上次基线、账号本地当前状态、云端当前状态三方合并；不同记录的改动自动合并，同一记录两端同时修改时暂停写入并保留冲突内容，等待用户处理。
- 当前发布分支已把匿名数据、每个登录账号的本地缓存和同步基线分别存储：旧版单一缓存只迁入匿名作用域，登录后只有用户明确选择“导入当前账号”才合并匿名内容；退出、当前设备撤销和账号注销会清理当前账号缓存，再恢复匿名数据。auth API 不可用时账户中心会进入离线状态，不再永久停在加载中。相关存储/同步回归 9/9、体验与基础设施回归 22/22、auth-api 回归 10/10、构建与 SSR 回归 2/2 均通过；本轮改动尚未部署。
- 当前发布分支已实现用户名、邮箱和密码注册登录：密码使用 Argon2id（19 MiB、2 次迭代、单线程），注册字段经过 NFKC 规范化、长度和字符白名单校验；登录不存在账号与错误密码统一返回，连续失败会逐级锁定。每次注册或登录签发新的 HttpOnly 会话，密码重置使用短期一次性令牌且数据库只存带 pepper 的摘要，成功重置会撤销该账号全部旧会话。生产环境禁止把调试重置码写入响应；正式 SMTP 投递适配器已实现，真实邮件仍待服务凭据和 staging 投递验证。
- 当前发布分支新增 `0006_credential_auth.sql`，扩展用户名、规范化邮箱、可选校园账号及验证状态、注册来源和最后登录时间，并增加密码凭据与一次性重置令牌表。认证 API、Argon2id 实际哈希、源码 ESLint、主站构建与 SSR、auth-api 生产依赖审计均通过；账号 UI 已在 390×844 与 1440×900 复核，无页面级横向溢出。该迁移已包含在 PR #10 的 PostgreSQL 17 空库双迁移与真实账号链中通过，本轮仍未部署。
- 当前发布分支已加入登录用户资料读写 API 和“我的 → 账号资料”：可修改用户名、显示名和可选校园账号，邮箱只读；服务端只接受明确白名单字段，用户名唯一性由数据库约束，校园账号发生变化会自动清除原验证状态。页面明确区分“已验证、待验证、未验证”，不把用户自行填写的学号当作真实学生身份。账号资料、CSRF、Mass Assignment 与作用域回归已纳入 auth-api 测试，本轮仍未部署。
- 当前发布分支新增 `0009_email_verification.sql` 与登录账号邮箱验证闭环：申请和确认都要求可信同源请求，申请还要求有效会话并按 IP+账号独立限流；数据库只保存带服务端 pepper 的令牌摘要，并把令牌绑定申请时的规范化邮箱。新申请会使旧令牌失效，确认时按当前账号、未过期、未消费和邮箱未变化条件原子消费，完成后废止该账号其余验证令牌。“我的 → 账号资料”已接入请求、输入和状态刷新；本地开发可在响应中取得一次性令牌，生产配置明确禁止该模式并默认关闭投递。正式 SMTP 模式使用 TLS 1.2+、拒绝无效证书、禁用文件/URL 内容读取，只发送纯文本一次性令牌；密码重置继续用统一 202 响应防账号枚举。适配器和注入式行为测试已通过，真实 SMTP 凭据、服务商投递和 PostgreSQL 17 迁移仍待环境验证，本轮未部署。校园账号验证仍未实现，未验证学号继续不作为学生身份凭据。
- 当前发布分支新增 `0007_user_avatars.sql` 和账号头像读写接口：只接收 JPEG、PNG、WebP，上传原图上限 5MB、最大边长 4096、最大 2000 万像素；服务端按文件魔数复核格式、拒绝动图与多页文件，纠正方向后裁切为 512×512 WebP，输出上限 512KB。数据库只保存处理后的 WebP 与摘要，不保存原图和 EXIF；写入要求有效会话、可信 Origin，并按账号与 IP 限流。公开读取只返回活跃账号头像，带 ETag 且缓存最多 5 分钟，避免删除后旧副本长期留存。头像处理与 API 回归 21/21 通过，本轮仍未部署。
- 当前发布分支已实现管理员安全后端：`0008_admin_security.sql` 增加服务端角色、AES-256-GCM 加密的 TOTP 因子、只存独立 pepper 摘要的单次恢复码、绑定基础会话的短期提升会话，以及拒绝更新/删除/截断的管理审计表。TOTP 使用 RFC 6238 的 SHA-1/6 位/30 秒/±1 时间步并由数据库条件更新原子阻断重放；密文以因子 ID 与用户 ID 作为 AAD，支持 key ID 轮换。管理员只能由显式运维命令按已有账号初始化，不会自动提升首个注册者；初始化会撤销全部旧会话，明文 TOTP 与 10 个 128 位恢复码只显示一次。
- 同域 `/api/admin/*` 已接入独立的 noindex 反向代理：匿名请求 401、普通用户在查询任何管理对象前统一 403；高风险读写必须持有与当前基础会话绑定的短期 `__Host-`、HttpOnly、Secure、SameSite=Strict 提升 Cookie。已实现管理状态、TOTP/恢复码提升与撤销、概览、脱敏用户列表、审计列表和账号启用/禁用 API；禁用账号、撤销其全部基础/提升会话与写入审计处于同一数据库事务，恢复账号不会复活旧会话。受保护的 `/admin` 值守台已接入上述真实 API，覆盖登录/权限/MFA/失效状态、统计、账号检索、带原因与乐观锁的停用恢复确认及审计时间线；入口只对当前管理员显示，但安全边界仍完全在服务端。页面带 noindex 元数据并加入 robots 禁止抓取，桌面与 390px 手机布局已用本地只读模拟数据视觉复核。auth-api 31/31 行为测试通过。迁移脚本已配置独立非 owner 运行角色，并撤销其修改审计表与迁移账本的权限；本机无 `sh`/Docker/PostgreSQL，真实迁移、并发原子性、数据库权限与真实账号浏览器 E2E 仍待 staging/CI 验证，本轮未部署。

## 课程数据模型

课程数据必须区分三层：

1. `Course`：目录课程，以课程号为主要标识，承载名称及未来的教材/资料关系。
2. `Section`：教学班，对应源表的一条开课记录，以 `sectionId` 标识，承载教师、课序号和主修班级。相同课程可有多个教师和教学班。
3. `Meeting`：教学班的一次固定上课安排。一个教学班可有多个星期/节次/教室组合，每个组合生成一条 schedule，并通过同一个 `sectionId` 关联。

每条 schedule 的 `weeks` 数组是周次判断的权威字段：

- `1-9周` → 1 至 9 周。
- `9-18周` → 9 至 18 周。
- `1-18周` → 1 至 18 周。
- 同时支持不连续区间和单双周。

禁止按课程名合并教学班，也禁止只取同一源行的第一个上课时间。选课界面先展示课程，再让用户选择具体教师/班次；加入一个班次时要一次加入该班次的全部 meeting。

## 关键业务规则

- 选择具体班级后，默认课表只导入该班实际对应的全部教师和全部时段。

- 登录用户可从“我的”或社区导航进入 `/community/saved`，管理云端收藏主题和已屏蔽账号；今日学习台不增加收藏卡片或社区信息流。
- 私人收藏与屏蔽列表使用当前会话和 PostgreSQL 权威关系表，按关系创建时间与 UUID 做有界 keyset 分页。取消收藏和解除屏蔽复用既有幂等写接口，不在浏览器另存影子副本。
- 已隐藏、删除或因双向屏蔽不可见的收藏仍允许本人清理关系，但响应不返回标题、正文摘要或作者；查询只接受唯一的 `limit/cursor` 参数，不公开邮箱、学号、会话或其他账号资料。
- 本地定向接口/数据层/体验契约 67/67、真实全迁移 PGlite 收藏→屏蔽清理→解除闭环、TypeScript、相关 ESLint、`git diff --check` 与生产构建通过；本切片未部署，仍须以 PR 完整 CI 复核。
- 主题详情的每个根回复线程都可由读者自主“收起本章”并随时展开；折叠只存在于当前页面内，不删除正文、不改变排序或治理状态，也不持久化用户画像。折叠摘要保留作者、时间和回应数量，并使用 `aria-expanded/aria-controls` 表达可访问状态。

## 当前发布分支：独立 staging 准备

- 仓库新增与生产完全分离的 `docker-compose.staging.yml`：三个自建镜像必须绑定完整 40 位 Git SHA，PostgreSQL、小影和 Caddy 使用独立命名卷，凭据与资料目录必须由仓库外绝对路径显式提供，默认只监听 `127.0.0.1:8443`。
- staging 预检会拒绝 `dufesh.cn`、生产 IP、生产共享目录、非 `_staging` 数据库、非 600 权限凭据、非 HTTPS 公网来源和未经批准的公网监听；无真实值会直接失败，不提供可误用的生产默认值。冒烟脚本同样拒绝生产目标。
- 主站应用容器补齐非 root 之外的只读文件系统、64MB 临时目录、禁止提权以及 CPU/内存/PID 限额。生产与 staging 的 Caddy 都只等待主应用健康，小影作为隔离的可选服务，其故障不再阻止主站和账号入口启动。
- 本地 staging/发布契约 8/8、TypeScript、Compose YAML 解析、生产构建与差异检查通过。本机没有 Docker/sh，尚未执行真实 Compose 解析、容器启动或外部 staging；相关证据必须由 Linux PR CI 和获批的独立 staging 提供。本轮未部署。
