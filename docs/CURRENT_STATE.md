# 东财之影：当前状态

最后更新：2026-07-29

## 产品

- 名称：东财之影。
- 面向东北财经大学学生的课程、个人课表、空教室与学习资料入口，允许校外访问。
- 移动端和微信内置浏览器优先，同时适配电脑。
- 首页核心是“今日学习台”，集中展示下一节课、日程、作业截止时间、空教室和常用入口。

## 当前技术状态

- 前端：React + TypeScript + vinext。
- 课程数据由 Excel 离线生成到 `public/data/course-data.json`。
- 当前个人档案、课表、日程和作业保存在浏览器 `localStorage`；微信登录和云端多设备同步尚未接入。
- AI 是未来可选增强功能，不得阻塞无 AI 用户的课程、课表、空教室和资料功能。
- 本地待验收版本已建立独立的 `product-system.css` 体验层，统一颜色、间距、圆角、焦点态和移动端交互规范。
- 今日学习台首屏已改为下一节课主卡、最近作业、规则建议和接下来三项安排；无作业时不显示空作业卡。
- 课程详情已支持按教师、星期、节次和冲突状态筛选教学班，并可暂存最多 4 个班次比较；加入时一次加入该教学班的全部时段。
- 手机课表已提供“近日（今天及未来两天）/整周”双视图；图片导出始终强制使用完整周课表。
- 以上体验改动当前只在本地预览，尚未发布到阿里云或备用站。
- 主站服务器：阿里云 ECS，Docker 应用由 Caddy 反向代理。
- 正式域名：`dufesh.cn` / `www.dufesh.cn`；域名是否公开解析取决于 ICP 备案状态。
- 私有预览：`https://dufesh.zzzhs66678.chatgpt.site`。

## 课程数据模型

课程数据必须区分三层：

1. `Course`：目录课程，以课程号为主要标识，承载名称及未来的教材/资料关系。
2. `Section`：教学班，对应源表的一条开课记录，以 `sectionId` 标识，承载教师、课序号和主修班级。相同课程可有多个教师和教学班。
3. `Meeting`：教学班的一次固定上课安排。一个教学班可有多个星期/节次/教室组合，每个组合生成一条 schedule，并通过同一个 `sectionId` 关联。

每条 schedule 的 `weeks` 数组是周次判断的权威字段：

- `1-9周` → 1 至 9 周。
- `9-18周` → 9 至 18 周。
- `1-18周` → 1 至 18 周。
- 同时支持不连续区间和单双周。

禁止按课程名合并教学班，也禁止只取同一源行的第一个上课时间。选课界面先展示课程，再让用户选择具体教师/班次；加入一个班次时要一次加入该班次的全部 meeting。

## 当前数据规模

- 19 个学院。
- 72 个专业。
- 1,759 门目录课程。
- 4,020 条专业—课程关系。
- 全校共有 4,986 条带具体时段的源教学班记录，展开后共 5,870 条 schedule。
- 五栋目标教学楼内共有 4,537 条源教学班记录，其中 831 条含多个上课时段，展开后共 5,417 条空教室占用记录。
- 五栋教学楼：之远楼、笃行楼、书音楼、播慧楼、砺金楼。

## 关键业务规则

- 选择具体班级后，默认课表只导入该班实际对应的全部教师和全部时段。
- 只选择专业、未选择班级时，不自动猜测教学班；用户从课程池自行选教师/班次。
- 全校选课保留体育场馆及五栋楼之外的上课地点；只有空教室计算限定在五栋目标教学楼。
- 同一时间允许保留多个课程或活动，但必须提示冲突。
- 空教室必须按当前教学周过滤，前九周课在后九周不占用，后九周课在前九周不占用。
- 一份资料只存一次，通过课程关系复用；无资料时隐藏入口，不显示空占位。
- 只有站长上传内容；用户评价功能未来另行设计审核机制。

- 全站构建：`npm run build`
- 发布采用不可变 release 目录并原子切换，保留上一版本用于回滚。
