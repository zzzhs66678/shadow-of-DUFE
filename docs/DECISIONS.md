# 东财之影：有效设计决定

| 编号 | 决定 | 原因 |
|---|---|---|
| D-001 | 课程、教学班、上课时段使用三层模型 | 同名课程可有多位教师，同一教师可教多个班，一个教学班可在多个时间上课 |
| D-002 | 生成阶段把周次解析成显式 `weeks` 数组 | 避免页面各自解析文本导致 `1-9`、`9-18`、单双周判断不一致 |
| D-003 | 选择具体班级才自动导入；未选班级不猜教学班 | 教师和时段属于具体教学班，取“第一条”会产生错误课表 |
| D-004 | 加入教学班时一次加入该班全部 meeting | 防止只出现每周第一次课 |
| D-005 | 同名课程不能直接合并，资料按确认后的课程关系复用 | 名称相同不代表课程号、教学内容或资料完全相同 |
| D-006 | 匿名档案与每个登录账号使用独立本地作用域；账号云端是登录后的权威来源，匿名数据只在用户明确选择后并入 | 既保留无账号可用性，也避免同浏览器切换账号时发生数据串号 |
| D-007 | AI 是可选增强层，核心功能不依赖 AI | 控制成本、隐私风险和 API 不可用时的产品退化 |
| D-008 | 不重写 Git 历史，以当前状态文档代替聊天回放 | 保留回滚能力，同时减少后续任务读取上下文的 token |
| D-009 | 服务器使用不可变 release 和原子切换 | 上传或构建期间不影响正在访问的用户，并能快速回滚 |
| D-010 | 全校选课 schedule 与五栋楼空教室占用分开统计 | 体育场馆及其他地点的课程必须可选，但不应进入五栋楼空教室计算 |
| D-011 | 普通用户的校园服务入口保持手机直达；只有主动开通的 VIP 才进入小影连接流程 | 保持免费用户简单轻量，同时把第三方授权和自动化控制在明确同意的小范围内 |
| D-012 | 小影不再出现在面向学生的主站界面，核心功能不得依赖小影；既有独立服务只保留为未公开、可单独停用的历史能力 | 用户已明确不需要小影；移除入口可减少无用选择，同时保证课表、空教室、课程与资料不受独立服务状态影响 |
| D-013 | 本地验证和未来云端使用同一外部连接抽象；第三方授权包加密存储且与主密钥分离，页面、日志和 AI 不接触明文 | 支持手机端无感同步与多设备使用，同时把凭据暴露面限制在专用连接服务 |
| D-014 | IGoLibrary 能力按东财之影的学生场景分层呈现；普通/明日预约、定时预约、空位发现、占座管理、手机控制、通知和高级设置都保留，外部写操作必须可审计且有频率上限；用户明确不需要手机现场 iBeacon 签到 | 不把桌面控制台原样搬进网站，也不因界面复杂而静默删功能；同时避免伪造现场状态和无上限高频请求 |
| D-015 | 主站不提供小影授权、日志、技术设置或入口；若历史独立服务仍保留，第三方协议覆盖只能由站长通过受信任版本文件维护 | 避免移动端和“我的”页面承载已取消的产品入口，同时让尚未移除的历史服务配置继续可审计、可回滚且不能指向任意主机 |
| D-016 | ECS 系统盘只承载应用和结构化数据，大文件与向量索引使用对象存储或外部存储 | 当前 40GB 系统盘已存约 6.8GB 资料，继续混放会挤占发布、日志和回滚空间 |
| D-017 | VIP 各自提供模型 API 密钥，AI 为可选操作入口；手动 UI 与 AI 共用同一校园动作服务 | 不让 AI 成为核心功能前置条件，避免两套预约/同步逻辑产生行为差异 |
| D-018 | 白果云同步直接读取课程、作业和通知接口，授权过期先刷新，失败才重新授权；结构化记录按外部 ID 幂等更新 | Cookie 不是稳定数据源，幂等同步可避免重复日程和多版本不一致 |
| D-019 | 小影以独立私有容器挂载到主站子路径，使用独立数据卷、主密钥、Cookie 路径和资源上限 | VIP 第三方授权与自动任务不应扩大普通用户主站的故障域或会话暴露面 |
| D-020 | 前端采用“校园导视 × 学术档案 × 日月时间轨”视觉体系；纸白、炭墨与朱红为主，松针绿只表达状态，动效必须尊重系统减少动态效果设置 | 形成东财之影自己的视觉语言，同时让今日学习台保持功能优先并避免蓝色模板化界面 |
| D-022 | 本次正式发布只以根目录 `MASTER_RELEASE_BRIEF.md` 作为产品需求与验收标准 | 避免历史路线图与本轮已明确升级范围发生冲突 |
| D-021 | 手机个人课表默认完整五天；空教室默认教学楼与楼层视图，时间/时长推荐只作为可展开增强项。用户点击空教室结果中的教室后直接进入该教室完整一周课表，不在结果页下方重复展开或要求逐日切换 | 高频查看任务应直接呈现结果，不能让推荐逻辑或冗余面板挡住原始数据，也不能用未经定位的数据声称“离你更近” |
| D-023 | 教师 UUID 与来源教师键分离；历史评价先进入私有待审核候选；教材按学期和教学班保存多项版本 | 姓名和学院都不能排除同名，历史文本不能冒充当前用户或自动推导评分，同一课程在不同教学班和学期可能使用不同教材 |
| D-024 | 历史教师评价的候选证据、管理员决定和公开评价分层保存；决定只允许在短期 MFA 提升事务中创建一次 | 防止未审核正文泄露、并发覆盖首个决定或审计失败后留下孤立公开评价，同时让 importer 只能回滚未批准候选 |
| D-025 | 课表只有在持有稳定 `teacher_id` 时才直达教师详情；当前姓名字段进入教师索引并由学院消歧 | 姓名不是唯一标识，直接按姓名选取首条会把同名教师的课程、教材和评价错误归并 |
| D-026 | 当前登录用户对同一教师只维护一条活动评价，修改使用版本号，删除及账号注销都撤下并去标识化而不硬删除 | 防止重复刷评和跨账号越权，保留冲突处理与必要审计边界，同时保证用户注销不会因评价外键或不可变触发器失败 |
| D-027 | `course-data.json` 保持完整课程事实唯一来源，首页只加载由同一生成器产出的不高于 750KB 轻量投影；课程库、课表、空教室、班级设置、课程搜索和详情再按需加载完整索引 | 保留全部既有课表 ID、周次和地点计算能力，同时消除首页被 3.22MB 完整索引阻塞，并防止轻量文件演变成第二套课程事实 |
| D-028 | 生产启动统一经过本仓库受限网关：vinext 只绑定回环端口，网关仅从 `dist/client` 放行构建哈希资产、课程/资料数据、站点图片、`.well-known` 和明确根文件 | 当前 vinext App Router 生产服务器不会可靠提供 public 数据和客户端资产；显式白名单既恢复生产水合与数据读取，也避免把服务端源码或任意构建文件暴露为静态资源 |
| D-029 | 公开长列表保持 20—40 条分页/游标或渲染窗口；课程选择器先按课程预分组并以 40 门为批次，筛选变化重置；没有 staging 性能证据时不引入 DOM 虚拟化 | 有界列表已经控制网络、计算和挂载规模；盲目虚拟化会增加键盘焦点、读屏顺序和移动端抽屉交互风险，且不能解决原先每张卡重复扫描完整时段的真正热点 |
| D-030 | 小影 HTTP、供应方和任务异常必须在服务边界转换为稳定错误码与固定公共文案；页面、任务结果和审计不得使用原始 `error.message` | 第三方响应、解析器提示和字段路径可能包含内部结构或凭据片段，直传会把校园服务故障升级为信息泄漏；白名单映射同时保留用户可行动的过期、超时和重试提示 |
| D-031 | 小影后台任务必须使用持久租约；过期只读任务可重领，可能已执行的第三方写入只能转人工核对；预约/取消确认的幂等结果按键摘要持久化，短期预览重启后失败关闭 | 本地数据库无法与校园第三方接口组成原子事务，崩溃后自动重放可能重复预约或取消；租约、旧令牌拒绝和持久执行账本能恢复本地状态，同时明确保留远端结果不确定性的安全边界 |
| D-032 | 小影正式邀请码必须设置 1—500 次批次上限并在事务内原子消费；换码废止旧码并重置新批次计数，缺配置拒绝启动 | 共享邀请码一旦泄漏会被批量注册；显式批次配额、条件更新和可验证轮换把影响限制在站长设定人数内，同时避免并发先查后写超额 |
| D-033 | CSP 由生成最终文档的服务持有：主站逐请求 nonce，小影按实际 HTML 生成 SHA-256；Caddy 不再用全局策略覆盖，动态样式例外仅限 `style-src-attr` | vinext 的可执行内联脚本只有在收到请求策略时才能自动带 nonce，小影静态页面更适合精确哈希；服务级策略既避免 `script-src 'unsafe-inline'`，也防止反向代理把不同页面强行降级到同一宽松规则 |
| D-034 | 正式应用只由 `https://dufesh.cn` 提供；`www` 与直接 IP 明文入口仅 308 到主域名同路径/查询，不能承载应用代理 | HSTS 不保护首次 IP 明文访问；单一来源可消除降级入口、重复索引、Cookie/Origin 混淆和小影授权来源分叉 |
| D-035 | 在 `image-size` 官方无修复期间，用项目内失败关闭包覆盖 vinext 依赖，并禁止 `app/` 本地图片 import/图片 metadata；产品图片走 public URL 与显式尺寸 | 当前功能不需要构建期通用图片探测；完全移除解析能力比维护未经上游验证的复杂格式补丁更可审计，也能让干净安装和生产镜像不再包含已知无限循环代码 |
| D-036 | 同一学期、课程、教学班、教师和教材序号最多只能有一条 `current/needs_review` 教材；不同来源导入先按稳定槽位获取排序事务锁，旧版本只保留为 `superseded`。来源教师键的姓名或学院快照变化时失败关闭，不静默改写身份 | 来源文件摘要不同也可能并发更新同一教学班；按文件加锁不能阻止双 current。教师来源键虽然稳定，但在没有身份版本审核机制时静默接受姓名或学院变化会把历史课程、教材与评价挂到错误的人 |
| D-037 | 教材预检中的姓名和学院组合只用于提出教师候选；只有该组合恰好对应一个来源教师键时才可写入该键，同学院同名对应多个来源键时保留为 unresolved/needs_review | 姓名和学院都不是唯一标识，`Map` 后写覆盖会把教材静默归给最后出现的同名教师；在没有具体来源键或人工确认前，缺少关联优于错误关联 |
| D-038 | 完整与轻量课程数据共享由最终 schedule 事实确定的 `catalogId`；数据库另存 `catalogId + scheduleId + teacher_id` 的可审计身份覆盖，只有唯一确认映射才直达教师 UUID，0/多/异常一律回退姓名索引消歧 | 不复制周次、教室等课程事实即可让映射随目录版本失效；既避免按姓名猜教师，也兼容共同授课、未覆盖课程、离线使用和未来映射修订 |
| D-039 | 教师评价讨论使用独立两级回复表，但复用社区的处罚、屏蔽、通知、举报、案件和双审计治理；隐藏内容只可原样恢复，已删除内容不可复活 | 避免为评价伪造社区主题或复制治理系统，同时防止作者在隐藏期间偷换正文后被管理员无意恢复为公开内容 |
| D-040 | 管理员账号名册使用上海自然日统计最近 30 天注册量，以稳定游标筛选和续读；用户内容入口只返回公开社区投影，不向后台浏览器暴露邮箱、学号、会话或私有资料 | 值守人员需要可解释的趋势和精确查找，但管理便利不能扩大普通账号隐私暴露面或绕过社区可见性边界 |
| D-041 | 校园高频写操作使用严格的每账号共享配额，并另设独立、宽松的网络总量配额；账号与网络不得共用同一小容量桶 | 校园网和宿舍网常有 NAT，共享 IP 不能让一个学生耗尽另一名学生的个人额度，同时仍需限制单账号滥用和异常出口总量 |
| D-042 | 教师公开评价只按正文查找；热议依据仍公开回复数，相关依据正文首次匹配位置；三种排序分别使用严格 keyset 游标 | 提供可解释、可分页且不依赖用户画像的发现能力，同时避免已隐藏回复影响热议或不同排序误用游标 |
| D-043 | 管理员主动内容巡查只能创建统一治理案件，不能提供绕过案件的直接隐藏/删除入口 | 评论管理既要能在没有举报时发现内容，也必须保留短期 MFA、状态机、作者通知、双审计和恢复路径 |
| D-044 | staging 使用独立 Compose 项目、仓库外凭据和资料目录、独立命名卷及完整 Git SHA；默认仅回环监听，生产域名/IP/共享目录与未批准公网绑定在预检中失败关闭 | 防止演练误连生产数据或把未验收服务公开，同时让同一提交的迁移、镜像、回滚和测试证据可复现 |
| D-045 | Caddy 启动只依赖主应用健康，小影保留独立健康检查但不进入主站启动门槛 | 小影是可选增强服务，其第三方故障、授权异常或维护不能扩大为首页、账号、课程与社区整体不可用 |
| D-046 | 五项主导航为今日、课表、空教室、课程和我的；课程页统一承接个人课程、全校课程库、教师评价和学习资料入口，但四类对象保持清晰分区。教师评价只属于具体教师档案，不升格为独立顶级功能 | “课程”比“学习档案”更直接；主任务、对象索引和用户贡献的地位不同。全站教师搜索必须进入姓名/学院消歧页，只有课表映射得到唯一稳定 UUID 时才直达详情 |
| D-047 | 教师教学班与教材必须保存具体 `YYYY-YYYY-fall/spring` 学期；已解析到稳定教师的教材导入必须在同一批次建立对应教学班事实并一同回滚 | 脱离学年的 `fall/spring` 会把不同年度记录混在一起；只落教材不落教学班会让教师档案出现“有教材但教学班为 0”的自相矛盾，并迫使 UI 用猜测掩盖数据缺口 |
| D-048 | 正式教务的完整学期响应是个人课表的权威来源，成功抓取后按学期持久保存，默认不周期重抓；导入或更新入口只放在课程页，今日和课表不重复出现。白果云当前周课程只用于作业关联，不冒充完整课表。同学期日常同步只刷新作业和通知，换学期或用户明确要求时才重抓课程关联 | 课表是低频权威快照，作业和通知是活数据；把低频导入放在每日入口会制造错误优先级，混为一次同步也会浪费第三方请求并可能漏掉后半学期课程 |
| D-049 | 教务导入由同域服务端代用户完成一次性 VPN 登录、官方短信续验和课表/考试双页面读取；学校要求二次认证时按单个绑定号码、未绑定号码或多个号码的官方语义继续，不绕过认证。教务密码、验证码与上游 Cookie 只存在于请求或五分钟内存事务，不写数据库、浏览器存储或普通日志。只保存规范化学期快照，任一页面登录失效或格式未知时整次失败关闭 | 让用户不再手工导出文件，同时把学校凭据暴露面限制在单次操作内；遵循学校二次认证边界，双页面原子结果可避免把“考试解析失败”误报为“暂无考试”，也不会用公共班级数据猜测个人教学班 |
| D-050 | 共用边缘 Caddy 可同时接入 production 与 staging ingress，但正式 app、auth-api 和小影必须使用 `production-*` 唯一网络别名，staging 只使用 `staging-*`；网关配置不得代理 Compose 自动生成的通用服务名 | 同一容器加入多个 Compose 网络后，Docker DNS 会让相同服务名产生歧义，可能把正式域名静默送入 staging 应用和数据库；环境专属别名把路由隔离变成可测试的不变量 |
| D-051 | vinext 的构建插件传递链在上游没有可用修复时，只允许对精确 advisory、精确锁定版本和限期复审做审计例外；该链必须从最终运行镜像剔除，并由生产模块加载和真实 HTTP 冒烟共同证明不属于运行时 | 直接关闭依赖审计会掩盖新增高危，盲目降级 vinext 会破坏现有构建；构建输入仅来自受信仓库，而运行镜像不保留可被请求触达的漏洞代码，依赖、修复建议或到期时间任一变化都会重新失败关闭 |
