# 东财之影：有效设计决定

| 编号 | 决定 | 原因 |
|---|---|---|
| D-001 | 课程、教学班、上课时段使用三层模型 | 同名课程可有多位教师，同一教师可教多个班，一个教学班可在多个时间上课 |
| D-002 | 生成阶段把周次解析成显式 `weeks` 数组 | 避免页面各自解析文本导致 `1-9`、`9-18`、单双周判断不一致 |
| D-003 | 选择具体班级才自动导入；未选班级不猜教学班 | 教师和时段属于具体教学班，取“第一条”会产生错误课表 |
| D-004 | 加入教学班时一次加入该班全部 meeting | 防止只出现每周第一次课 |
| D-005 | 同名课程不能直接合并，资料按确认后的课程关系复用 | 名称相同不代表课程号、教学内容或资料完全相同 |
| D-006 | 当前先用本地匿名档案，账号与云同步以后兼容迁移 | 微信登录资格和备案尚未具备，但基础功能不应等待 |
| D-007 | AI 是可选增强层，核心功能不依赖 AI | 控制成本、隐私风险和 API 不可用时的产品退化 |
| D-008 | 不重写 Git 历史，以当前状态文档代替聊天回放 | 保留回滚能力，同时减少后续任务读取上下文的 token |
| D-009 | 服务器使用不可变 release 和原子切换 | 上传或构建期间不影响正在访问的用户，并能快速回滚 |
| D-010 | 全校选课 schedule 与五栋楼空教室占用分开统计 | 体育场馆及其他地点的课程必须可选，但不应进入五栋楼空教室计算 |
| D-011 | 校园常用服务只做用户手机端直达，不由本站代理或保存学校 Cookie | 复用学校页面已有登录状态，同时避免服务器负载和账号安全风险 |
| D-012 | “小影”AI 模式仅向邀请码 VIP 开放，普通用户不显示入口且核心功能不依赖 AI | 控制早期成本与风险，并保证课表、空教室和资料体验不受影响 |
| D-013 | 白果云和图书馆第三方会话优先留在用户本地执行器，云端只保存结构化记录、设备公钥和任务结果 | 降低 Cookie 集中泄露、服务器负载和第三方接口风险 |
| D-014 | 图书馆首版只允许查询、收藏座位、普通/明日预约和取消，外部写操作必须预览并确认 | 满足“预约常用位置”的核心价值，同时避免抢座、占座和远程签到风险 |
| D-015 | ECS 系统盘只承载应用和结构化数据，大文件与向量索引使用对象存储或外部存储 | 当前 40GB 系统盘已存约 6.8GB 资料，继续混放会挤占发布、日志和回滚空间 |
